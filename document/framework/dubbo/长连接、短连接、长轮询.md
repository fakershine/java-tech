# 长连接、短连接、长轮询总结

这三个概念常用于网络通信和实时消息场景。

核心区别：

```text
短连接：请求一次，连接一次，用完关闭
长连接：连接建立后保持复用
长轮询：客户端发请求，服务端有数据才返回，没有数据就挂起等待
```

---

## 1. 短连接

### 原理

每次请求都新建连接，请求完成后关闭连接。

```text
建立连接
  ↓
发送请求
  ↓
返回响应
  ↓
关闭连接
```

### 特点

- 实现简单。
- 服务端连接占用少。
- 每次都要建连，开销大。
- 不适合高频请求。

### 场景

```text
低频接口调用
简单 HTTP 请求
访问频率不高的系统
```

---

## 2. 长连接

### 原理

客户端和服务端建立连接后，不立即关闭，后续请求继续复用该连接。

```text
建立连接
  ↓
请求 1 / 响应 1
  ↓
请求 2 / 响应 2
  ↓
请求 3 / 响应 3
  ↓
空闲超时后关闭
```

HTTP/1.1 默认支持：

```http
Connection: keep-alive
```

### 特点

- 减少 TCP 握手开销。
- 降低连接创建和关闭成本。
- 适合频繁请求。
- 服务端需要维护连接，占用资源。
- 需要心跳和超时检测。

### 场景

```text
HTTP KeepAlive
数据库连接池
RPC 连接池
Netty 长连接
IM 聊天
网关连接复用
```

---

## 3. 长轮询

### 原理

客户端发起请求后，如果服务端没有数据，不立即返回，而是挂起一段时间。

```text
客户端请求
  ↓
服务端没有数据，先不返回
  ↓
等待数据到来
  ↓
有数据：立即返回
  ↓
超时无数据：返回空结果
  ↓
客户端再次发起请求
```

### 特点

- 比普通轮询实时性更好。
- 比 WebSocket 实现简单。
- 服务端会挂起请求，占用连接和线程/协程资源。
- 超时后客户端需要重新请求。

### 场景

```text
消息通知
扫码登录
订单状态变化
低频实时推送
配置变更监听
Nacos 配置监听
```

---

## 4. 普通轮询 vs 长轮询

### 普通轮询

客户端定时请求：

```text
每 3 秒请求一次
```

缺点：

```text
实时性差
无数据时也频繁请求
浪费资源
```

---

### 长轮询

服务端无数据时挂起请求：

```text
有数据立即返回
没数据等待到超时
```

优点：

```text
减少无效请求
实时性更好
```

---

## 5. 长连接和长轮询区别

| 对比项 | 长连接 | 长轮询 |
|---|---|---|
| 核心 | 连接保持复用 | 请求挂起等待数据 |
| 连接状态 | 长时间保持 | 每次请求仍会结束 |
| 数据推送 | 可以服务端主动推送 | 服务端等到有数据才响应 |
| 实时性 | 高 | 较高 |
| 实现复杂度 | 较高 | 中等 |
| 典型技术 | WebSocket、TCP、Netty | HTTP 长轮询 |

---

## 6. 短连接、长连接、长轮询对比

| 对比项 | 短连接 | 长连接 | 长轮询 |
|---|---|---|---|
| 连接是否复用 | 否 | 是 | 一般复用 HTTP 连接，但请求会结束 |
| 实时性 | 差 | 高 | 较高 |
| 服务端资源占用 | 低 | 较高 | 中高 |
| 建连开销 | 高 | 低 | 中等 |
| 实现复杂度 | 低 | 中高 | 中 |
| 适合场景 | 低频请求 | 高频通信、实时通信 | 简单实时通知 |

---

## 7. 和 WebSocket 的关系

WebSocket 是典型长连接。

```text
客户端和服务端建立一次连接
  ↓
双方可以双向通信
  ↓
服务端可以主动推送消息
```

适合：

```text
IM 聊天
实时行情
在线游戏
实时协作
消息推送
```

长轮询更像是：

```text
没有 WebSocket 时，用 HTTP 模拟服务端推送
```

---

## 8. 总结

短连接是每次请求都新建连接，请求结束后关闭，适合低频请求，但频繁建连开销大。

长连接是连接建立后保持一段时间，多个请求复用同一个连接，可以减少 TCP 握手和断开成本，适合高频请求和实时通信，但服务端需要维护连接资源。

长轮询是客户端发起请求后，服务端没有数据就先挂起，有数据再返回，超时则返回空结果，客户端收到响应后继续发起下一次请求。它比普通轮询实时性更好，也减少了无效请求，适合扫码登录、消息通知、配置监听等场景。

一句话总结：

```text
短连接 = 用完就关；
长连接 = 建一次，多次用；
长轮询 = 请求来了先等，有数据再返回。
```
