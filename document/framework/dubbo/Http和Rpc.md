# HTTP 和 RPC 总结

HTTP 和 RPC 都可以用于服务之间通信，但关注点不同。

```text
HTTP 更偏通信协议
RPC 更偏远程调用框架
```

---

## 1. 什么是 HTTP

HTTP 是一种应用层通信协议，常用于浏览器、前端、网关、第三方系统和后端服务之间通信。

常见调用方式：

```text
GET /users/1001
POST /orders
```

常见数据格式：

```text
JSON
XML
Form
```

---

## 2. 什么是 RPC

RPC 全称是 Remote Procedure Call，远程过程调用。

它的目标是：

```text
像调用本地方法一样调用远程服务
```

示例：

```java
User user = userService.getUser(1001L);
```

表面是本地方法调用，实际底层完成了：

```text
动态代理
  ↓
序列化
  ↓
网络传输
  ↓
服务端反射调用
  ↓
结果返回
```

常见 RPC 框架：

```text
Dubbo
gRPC
Thrift
Motan
```

---

## 3. HTTP 和 RPC 的核心区别

| 对比项 | HTTP | RPC |
|---|---|---|
| 定位 | 通信协议 | 远程调用框架 / 调用模型 |
| 调用方式 | 基于 URL 和 HTTP Method | 像调用本地方法 |
| 常见协议 | HTTP/1.1、HTTP/2 | TCP、HTTP/2、自定义协议 |
| 数据格式 | JSON、XML、Form | Hessian、Protobuf、Kryo、JSON |
| 易用性 | 通用、简单 | 对内部服务调用更友好 |
| 性能 | 一般略低 | 通常更高 |
| 跨语言 | 很好 | 取决于框架和协议 |
| 可读性 | 强，便于调试 | 二进制协议调试不方便 |
| 适用场景 | 对外接口、前后端调用 | 内部微服务调用 |

---

## 4. HTTP 调用流程

```text
客户端构造 HTTP 请求
  ↓
通过 URL 访问服务
  ↓
服务端 Controller 接收请求
  ↓
执行业务逻辑
  ↓
返回 JSON 响应
```

示例：

```http
GET /user/1001
```

返回：

```json
{
  "id": 1001,
  "name": "Tom"
}
```

---

## 5. RPC 调用流程

```text
客户端调用接口方法
  ↓
动态代理拦截
  ↓
封装请求对象
  ↓
序列化
  ↓
网络传输
  ↓
服务端反序列化
  ↓
反射调用真实方法
  ↓
返回结果
```

示例：

```java
User user = userService.getUser(1001L);
```

底层实际会变成一次远程网络调用。

---

## 6. HTTP 的优势

- 通用性强。
- 跨语言能力好。
- 调试方便。
- 浏览器、网关、前端天然支持。
- 适合对外开放 API。
- 生态成熟。

---

## 7. HTTP 的劣势

- 报文相对较大。
- 性能通常不如二进制 RPC。
- 接口调用不如 RPC 那样面向方法。
- 服务治理能力需要额外组件支持。

---

## 8. RPC 的优势

- 调用方式像本地方法，开发体验好。
- 性能通常更高。
- 可以使用高效二进制序列化。
- 内置服务治理能力更强。
- 支持注册发现、负载均衡、超时、重试、熔断等能力。

---

## 9. RPC 的劣势

- 框架依赖较强。
- 调试不如 HTTP 直观。
- 跨语言能力取决于协议和框架。
- 服务之间耦合度可能更高。
- 对版本管理要求更高。

---

## 10. 什么时候用 HTTP

适合：

```text
对外开放接口
前后端交互
第三方系统对接
网关入口请求
跨语言简单调用
```

例如：

```text
APP 调后端接口
前端调后端接口
第三方支付回调
开放平台 API
```

---

## 11. 什么时候用 RPC

适合：

```text
内部微服务调用
高性能服务调用
强服务治理场景
Java 服务之间调用
复杂分布式系统内部通信
```

例如：

```text
订单服务调用库存服务
支付服务调用账户服务
用户服务调用积分服务
```

---

## 12. HTTP 和 RPC 的关系

HTTP 和 RPC 不是完全对立的。

RPC 可以基于 HTTP 实现。

例如：

```text
gRPC 基于 HTTP/2
Dubbo Triple 基于 HTTP/2
```

所以更准确地说：

```text
HTTP 是通信协议
RPC 是调用方式 / 框架思想
RPC 可以基于 TCP，也可以基于 HTTP
```

---

## 13. 总结

HTTP 是一种通用应用层协议，常用于前后端通信、对外 API 和第三方系统集成。它简单、通用、跨语言好、调试方便，但性能和服务治理能力通常需要额外增强。

RPC 是远程过程调用，目标是让远程调用像本地方法调用一样。RPC 框架通常会封装动态代理、序列化、网络通信、服务注册发现、负载均衡、超时重试、熔断降级等能力，更适合内部微服务之间调用。

一句话总结：

```text
HTTP 更适合对外开放和通用通信；
RPC 更适合内部微服务之间的高性能调用和服务治理。
```
