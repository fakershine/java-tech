# Nacos 是 AP 还是 CP

Nacos **既支持 AP，也支持 CP**，不是单纯的 AP 或 CP。

核心结论：

```text
临时实例：AP
持久实例：CP
配置中心：通常依赖数据库保证一致性
```

---

## 1. 注册中心场景

### 临时实例：AP

默认微服务注册一般使用 **临时实例**。

特点：

```text
客户端定时发送心跳
心跳超时后实例被标记不健康或删除
优先保证可用性
```

Nacos 临时实例使用 **Distro 协议**，偏 AP，用来保证注册中心高可用。:contentReference[oaicite:0]{index=0}

适合：

```text
普通微服务注册发现
服务实例频繁上下线
优先保证服务发现可用
```

---

### 持久实例：CP

持久实例更强调数据一致性。

特点：

```text
实例不会因为心跳断开就直接删除
服务端主动探活
更强调节点之间数据一致
```

Nacos 持久实例使用 **JRaft / Raft 协议**，偏 CP，用来保证强一致性。:contentReference[oaicite:1]{index=1}

适合：

```text
固定服务实例
基础设施服务
对一致性要求更高的场景
```

---

## 2. 配置中心场景

Nacos 配置中心主要关注配置数据一致性。

通常生产环境会使用外部数据库，比如 MySQL 存储配置数据，多个 Nacos Server 共享同一份配置存储。

简单理解：

```text
配置中心更偏一致性
注册中心临时实例更偏可用性
```

Nacos 官方文档也提到，Nacos 在单个集群中会同时运行 CP 协议和 AP 协议，因为服务发现和配置管理对一致性的要求不同。:contentReference[oaicite:2]{index=2}

---

## 3. 总结

```text
Nacos 既支持 AP，也支持 CP。

在注册中心场景下，如果是临时实例，Nacos 使用 Distro 协议，偏 AP，优先保证可用性，这也是普通微服务默认常见模式。

如果是持久实例，Nacos 使用 JRaft / Raft 协议，偏 CP，优先保证数据一致性。

配置中心场景更关注配置一致性，生产环境通常通过外部数据库存储配置，保证配置数据一致。
```

一句话总结：

```text
Nacos 不是单纯 AP 或 CP；
临时实例走 AP，持久实例走 CP，配置中心更偏一致性。
```
