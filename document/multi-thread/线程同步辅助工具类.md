# 线程同步辅助工具类总结

Java 中常见的线程同步辅助工具类主要在 `java.util.concurrent` 包下，用于协调多个线程之间的执行顺序、并发数量和数据交换。

常见工具类包括：

- CountDownLatch
- CyclicBarrier
- Semaphore
- Phaser
- Exchanger
- LockSupport

---

## 1. CountDownLatch

### 实现原理

`CountDownLatch` 是一个倒计时门闩，用于让一个或多个线程等待其他线程执行完成。

内部维护一个计数器：

```text
初始计数 = N
每执行一次 countDown()，计数减 1
当计数减到 0 时，await() 阻塞的线程被唤醒
```

示例：

```java
CountDownLatch latch = new CountDownLatch(3);

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务
        latch.countDown();
    }).start();
}

latch.await();
System.out.println("所有任务执行完成");
```

### 特点

- 计数器只能递减。
- 计数到 0 后不能重置。
- 适合一个线程等待多个线程完成。

### 适用场景

- 主线程等待多个子线程执行完成。
- 多个服务初始化完成后再启动主流程。
- 并发任务结果汇总。

## 2. CyclicBarrier

### 实现原理

`CyclicBarrier` 是循环屏障，用于让多个线程互相等待，直到所有线程都到达屏障点后再一起继续执行。

内部维护一个计数器：

```text
指定参与线程数 = N
每个线程调用 await()
线程到达屏障后阻塞
当第 N 个线程到达后，所有线程同时放行
```

示例：

```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("所有线程都到达屏障点");
});

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        try {
            // 执行第一阶段任务
            barrier.await();

            // 执行第二阶段任务
        } catch (Exception e) {
            e.printStackTrace();
        }
    }).start();
}
```

### 特点

- 可以重复使用。
- 多个线程互相等待。
- 可以设置屏障任务 `barrierAction`。
- 任意线程异常可能导致屏障破坏。

### 适用场景

- 多线程分阶段任务。
- 多个线程都准备好后一起执行。
- 并行计算阶段同步。

---

## 3. Semaphore

### 实现原理

`Semaphore` 是信号量，用于控制同时访问某个资源的线程数量。

内部维护一组许可证：

```text
acquire()：获取许可证，获取不到则阻塞
release()：释放许可证
```

示例：

```java
Semaphore semaphore = new Semaphore(3);

for (int i = 0; i < 10; i++) {
    new Thread(() -> {
        try {
            semaphore.acquire();

            // 访问受限资源

        } catch (InterruptedException e) {
            e.printStackTrace();
        } finally {
            semaphore.release();
        }
    }).start();
}
```

### 特点

- 可以控制并发访问数量。
- 可以实现限流。
- 支持公平和非公平模式。
- 许可证可以多个获取和释放。

### 适用场景

- 控制接口并发数。
- 控制数据库连接数量。
- 控制文件上传并发数。
- 控制第三方接口调用并发。

---

## 4. Phaser

### 实现原理

`Phaser` 是一个更灵活的多阶段线程同步工具，可以理解为增强版的 `CyclicBarrier`。

它支持：

- 动态注册线程。
- 动态注销线程。
- 多阶段同步。
- 分阶段推进。

示例：

```java
Phaser phaser = new Phaser(3);

for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 第一阶段
        phaser.arriveAndAwaitAdvance();

        // 第二阶段
        phaser.arriveAndAwaitAdvance();

        // 第三阶段
        phaser.arriveAndDeregister();
    }).start();
}
```

### 特点

- 支持多阶段任务。
- 支持动态增加或减少参与线程。
- 比 `CyclicBarrier` 更灵活。
- 使用复杂度更高。

### 适用场景

- 多阶段任务同步。
- 任务参与线程数量不固定。
- 分阶段批处理任务。
- 复杂并行计算。

---

## 5. Exchanger

### 实现原理

`Exchanger` 用于两个线程之间交换数据。

两个线程都调用 `exchange()` 后，彼此交换数据并继续执行。

示例：

```java
Exchanger<String> exchanger = new Exchanger<>();

new Thread(() -> {
    try {
        String result = exchanger.exchange("线程 A 的数据");
        System.out.println("A 收到：" + result);
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
}).start();

new Thread(() -> {
    try {
        String result = exchanger.exchange("线程 B 的数据");
        System.out.println("B 收到：" + result);
    } catch (InterruptedException e) {
        e.printStackTrace();
    }
}).start();
```

### 特点

- 只能用于两个线程之间交换数据。
- 一个线程先到会阻塞等待另一个线程。
- 支持超时等待。

### 适用场景

- 两个线程交换计算结果。
- 生产者和消费者交换缓冲区。
- 数据校验和比对。

---

## 6. LockSupport

### 实现原理

`LockSupport` 是线程阻塞和唤醒的基础工具类，很多并发组件底层都依赖它。

核心方法：

```java
LockSupport.park();
LockSupport.unpark(thread);
```

含义：

```text
park()：阻塞当前线程
unpark(thread)：唤醒指定线程
```

示例：

```java
Thread thread = new Thread(() -> {
    System.out.println("线程开始阻塞");
    LockSupport.park();
    System.out.println("线程被唤醒");
});

thread.start();

Thread.sleep(1000);
LockSupport.unpark(thread);
```

### 特点

- 可以精准唤醒指定线程。
- 不需要配合 synchronized 使用。
- `unpark()` 可以先于 `park()` 调用。
- 是 AQS、ReentrantLock 等组件的底层基础。

### 适用场景

- 自定义锁。
- 自定义同步器。
- 线程阻塞和唤醒控制。
- 理解 AQS 底层原理。

## 7. 常见工具类对比

| 工具类 | 核心作用 | 是否可复用 | 适用场景 |
|---|---|---|---|
| CountDownLatch | 一个或多个线程等待其他线程完成 | 否 | 主线程等待子任务完成 |
| CyclicBarrier | 多个线程互相等待到达屏障 | 是 | 多线程分阶段执行 |
| Semaphore | 控制并发线程数量 | 是 | 限流、资源池控制 |
| Phaser | 多阶段线程同步 | 是 | 复杂阶段任务同步 |
| Exchanger | 两个线程交换数据 | 是 | 双线程数据交换 |
| LockSupport | 阻塞和唤醒线程 | 是 | 自定义同步组件 |

---

## 8. CountDownLatch 和 CyclicBarrier 区别

| 对比项 | CountDownLatch | CyclicBarrier |
|---|---|---|
| 核心作用 | 一个线程等多个线程完成 | 多个线程互相等待 |
| 是否可复用 | 不可复用 | 可复用 |
| 计数方式 | countDown 递减 | await 到达屏障 |
| 唤醒条件 | 计数减到 0 | 所有线程都到达屏障 |
| 典型场景 | 主线程等待子线程 | 多线程分阶段同步 |

简单理解：

```text
CountDownLatch：别人完成后，我再继续。
CyclicBarrier：大家都到齐后，一起继续。
```

---

## 9. Semaphore 和 CountDownLatch 区别

| 对比项 | Semaphore | CountDownLatch |
|---|---|---|
| 核心作用 | 控制并发数量 | 等待任务完成 |
| 是否可复用 | 可复用 | 不可复用 |
| 计数变化 | acquire 减，release 加 | 只能 countDown 减 |
| 典型场景 | 限流、资源控制 | 等待多个线程结束 |

简单理解：

```text
Semaphore：控制同时能进来几个线程。
CountDownLatch：等待几个线程都执行完。
```

---

## 10. 总结

Java 中常见的线程同步辅助工具类有 `CountDownLatch`、`CyclicBarrier`、`Semaphore`、`Phaser`、`Exchanger` 和 `LockSupport`。

`CountDownLatch` 用于让一个线程等待多个线程执行完成，计数器减到 0 后放行，但不能重复使用。

`CyclicBarrier` 用于让多个线程互相等待，所有线程都到达屏障点后一起继续执行，并且可以重复使用。

`Semaphore` 用于控制同时访问资源的线程数量，常用于限流、连接池、资源池等场景。

`Phaser` 是更灵活的多阶段同步工具，支持动态注册和注销线程，适合复杂的分阶段任务。

`Exchanger` 用于两个线程之间交换数据。

`LockSupport` 是线程阻塞和唤醒的底层工具，常用于实现锁和同步器。

一句话总结：

```text
CountDownLatch 用来等任务完成，CyclicBarrier 用来等线程集合，Semaphore 用来控并发数量，Phaser 用来做多阶段同步，Exchanger 用来交换数据，LockSupport 用来阻塞和唤醒线程。
```
