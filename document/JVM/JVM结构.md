# JVM 结构总结

JVM 主要由三部分组成：

```text
类加载子系统
运行时数据区
执行引擎
```

整体结构：

```text
Java 源码
  ↓ 编译
.class 字节码
  ↓
类加载子系统
  ↓
运行时数据区
  ↓
执行引擎
  ↓
操作系统 / 硬件
```

---

## 1. 类加载子系统

### 作用

类加载子系统负责把 `.class` 字节码文件加载到 JVM 中，并生成对应的 `Class` 对象。

类加载过程：

```text
加载 -> 验证 -> 准备 -> 解析 -> 初始化
```

### 各阶段说明

| 阶段 | 说明 |
|---|---|
| 加载 | 读取 `.class` 文件，生成 Class 对象 |
| 验证 | 校验字节码是否合法 |
| 准备 | 给静态变量分配内存并设置默认值 |
| 解析 | 将符号引用转换为直接引用 |
| 初始化 | 执行静态变量赋值和静态代码块 |

示例：

```java
static int count = 10;
```

准备阶段：

```text
count = 0
```

初始化阶段：

```text
count = 10
```

---

## 2. 运行时数据区

运行时数据区是 JVM 运行 Java 程序时使用的内存区域。

主要包括：

```text
程序计数器
Java 虚拟机栈
本地方法栈
堆
方法区
运行时常量池
```

---

## 3. 程序计数器

### 作用

程序计数器用于记录当前线程正在执行的字节码指令地址。

```text
线程执行到哪一行字节码，由程序计数器记录
```

### 特点

- 线程私有。
- 占用内存很小。
- 不会发生 OOM。
- 线程切换后可以恢复执行位置。

### 面试点

程序计数器是 JVM 中唯一一个不会出现 `OutOfMemoryError` 的区域。

---

## 4. Java 虚拟机栈

### 作用

Java 虚拟机栈用于存储 Java 方法调用过程中的栈帧。

每调用一个方法，就会创建一个栈帧。

```text
方法调用
  ↓
创建栈帧入栈
  ↓
方法执行完成
  ↓
栈帧出栈
```

### 栈帧中包含

| 内容 | 说明 |
|---|---|
| 局部变量表 | 存放方法参数和局部变量 |
| 操作数栈 | 字节码执行时的临时计算区域 |
| 动态链接 | 指向运行时常量池的方法引用 |
| 方法返回地址 | 方法执行完后返回的位置 |

### 常见异常

| 异常 | 原因 |
|---|---|
| StackOverflowError | 栈深度过深，例如递归调用 |
| OutOfMemoryError | 栈扩展时内存不足 |

---

## 5. 本地方法栈

### 作用

本地方法栈用于执行 Native 方法。

例如：

```java
native void method();
```

### 特点

- 线程私有。
- 服务于 JNI 本地方法。
- 和 Java 虚拟机栈类似。

### 常见异常

```text
StackOverflowError
OutOfMemoryError
```

---

## 6. 堆

### 作用

堆是 JVM 中最大的一块内存区域，主要用于存放对象实例和数组。

```java
User user = new User();
```

其中 `new User()` 创建的对象一般存放在堆中。

### 特点

- 线程共享。
- GC 主要管理区域。
- 是 OOM 最常见区域。

### 堆内存划分

常见分代模型：

```text
堆
├── 新生代
│   ├── Eden
│   ├── Survivor From
│   └── Survivor To
└── 老年代
```

### 新生代

主要存放新创建的对象。

大多数对象朝生夕死，会很快被 Young GC 回收。

### 老年代

主要存放生命周期较长的对象。

对象经过多次 Young GC 后仍然存活，可能晋升到老年代。

### 常见异常

```text
java.lang.OutOfMemoryError: Java heap space
```

---

## 7. 方法区

### 作用

方法区用于存放类相关信息。

主要包括：

- 类信息。
- 字段信息。
- 方法信息。
- 静态变量。
- 运行时常量池。
- JIT 编译后的代码缓存。

### JDK 版本区别

| JDK 版本 | 方法区实现 |
|---|---|
| JDK 7 及以前 | 永久代 PermGen |
| JDK 8 及以后 | 元空间 Metaspace |

### 元空间特点

JDK 8 后，方法区由元空间实现。

```text
元空间使用的是本地内存，不再直接占用 JVM 堆内存
```

### 常见异常

JDK 8 以后：

```text
java.lang.OutOfMemoryError: Metaspace
```

---

## 8. 运行时常量池

### 作用

运行时常量池是方法区的一部分。

主要存放：

- 字面量。
- 符号引用。
- 类和方法引用。
- 编译期生成的常量。

例如：

```java
String s = "abc";
```

`"abc"` 就可能进入字符串常量池。

---

## 9. 执行引擎

### 作用

执行引擎负责执行字节码指令。

主要包括：

```text
解释器
即时编译器 JIT
垃圾回收器 GC
```

---

## 10. 解释器

### 实现原理

解释器逐行解释执行字节码。

```text
字节码指令
  ↓
解释一条
  ↓
执行一条
```

### 优势

- 启动快。
- 不需要编译成本。

### 劣势

- 长期执行效率不如机器码。

---

## 11. JIT 即时编译器

### 实现原理

JIT 会把热点代码编译成本地机器码，提高执行效率。

```text
热点方法
  ↓
JIT 编译
  ↓
机器码
  ↓
直接执行
```

### 优势

- 提高长期运行性能。
- 热点代码执行效率高。

### 常见优化

- 方法内联。
- 逃逸分析。
- 锁消除。
- 标量替换。
- 循环优化。

---

## 12. 垃圾回收器

### 作用

垃圾回收器负责自动回收不再使用的对象。

主要管理区域：

```text
堆
方法区 / 元空间部分数据
```

常见垃圾收集器：

- Serial GC
- Parallel GC
- CMS GC
- G1 GC
- ZGC
- Shenandoah GC

---

## 13. 本地接口 JNI

### 作用

JNI 允许 Java 调用其他语言实现的本地方法，例如 C / C++。

```java
public native void callNative();
```

常见用途：

- 调用系统底层能力。
- 调用 C/C++ 库。
- 提升某些底层能力支持。

---

## 14. JVM 内存区域对比

| 区域 | 是否线程共享 | 存放内容 | 常见异常 |
|---|---|---|---|
| 程序计数器 | 否 | 当前线程执行位置 | 无 |
| Java 虚拟机栈 | 否 | 方法栈帧 | StackOverflowError / OOM |
| 本地方法栈 | 否 | Native 方法调用 | StackOverflowError / OOM |
| 堆 | 是 | 对象实例、数组 | Java heap space |
| 方法区 | 是 | 类信息、静态变量、常量池 | Metaspace |
| 运行时常量池 | 是 | 字面量、符号引用 | OOM |

---

## 15. JVM 结构总结

JVM 主要由 **类加载子系统、运行时数据区和执行引擎** 组成。

类加载子系统负责把 `.class` 字节码加载到 JVM 中，类加载过程包括加载、验证、准备、解析和初始化。

运行时数据区包括程序计数器、Java 虚拟机栈、本地方法栈、堆、方法区和运行时常量池。其中程序计数器、虚拟机栈、本地方法栈是线程私有的；堆和方法区是线程共享的。堆主要存放对象实例，是 GC 的主要区域；方法区主要存放类信息、静态变量、常量池等，JDK 8 后由元空间实现。

执行引擎负责执行字节码，主要包括解释器、JIT 即时编译器和垃圾回收器。

一句话总结：

```text
JVM 结构 = 类加载子系统 + 运行时数据区 + 执行引擎；
运行时数据区 = 程序计数器 + 虚拟机栈 + 本地方法栈 + 堆 + 方法区。
```
