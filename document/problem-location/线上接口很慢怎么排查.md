# 线上接口很慢怎么排查

线上接口变慢，本质是要定位慢在哪里：

```text
客户端
  ↓
网关
  ↓
应用服务
  ↓
缓存 / 数据库 / MQ / RPC / 第三方接口
```

排查思路：

```text
先确认范围
再看链路耗时
再定位瓶颈
最后优化和验证
```

---

## 1. 先确认问题范围

先判断是：

```text
单个接口慢
多个接口慢
整个服务慢
所有服务都慢
```

重点看：

- 慢的是哪个接口。
- 从什么时候开始慢。
- 是否和发版、流量上涨、配置变更有关。
- 是平均 RT 慢，还是 P95 / P99 慢。
- 是否伴随错误率升高。

常看指标：

```text
QPS
RT
P95 / P99
错误率
超时率
CPU
内存
GC
线程数
数据库连接数
Redis 响应时间
MQ 积压
```

---

## 2. 看链路追踪

如果有 SkyWalking、Zipkin、Jaeger、OpenTelemetry，优先看链路。

重点看每个阶段耗时：

```text
网关耗时
应用处理耗时
数据库耗时
Redis 耗时
RPC 调用耗时
第三方接口耗时
MQ 发送耗时
```

链路追踪可以快速判断：

```text
慢在应用内部
还是慢在下游依赖
```

---

## 3. 排查应用服务

### 3.1 CPU 是否过高

查看 CPU：

```bash
top
```

如果 CPU 高，继续查 Java 线程：

```bash
top -Hp <pid>
```

再用：

```bash
jstack <pid>
```

定位高 CPU 线程在执行什么代码。

常见原因：

```text
死循环
大量计算
频繁 GC
正则回溯
JSON 序列化过大
日志打印过多
锁竞争严重
```

---

### 3.2 线程池是否打满

重点看：

```text
业务线程池
Tomcat 线程池
Dubbo 线程池
异步任务线程池
数据库连接池
HTTP 客户端连接池
```

如果线程池打满：

```text
请求排队
RT 上升
甚至超时
```

常见原因：

```text
下游接口慢
数据库慢
锁等待
线程池配置过小
任务执行时间过长
```

---

### 3.3 是否有锁竞争

用 `jstack` 查看是否大量线程处于：

```text
BLOCKED
WAITING
TIMED_WAITING
```

重点关注：

```text
synchronized 锁
ReentrantLock
分布式锁
数据库行锁
Redis 锁
```

常见问题：

```text
锁粒度太大
锁内逻辑太慢
锁内调用外部接口
热点数据竞争
```

---

### 3.4 JVM GC 是否异常

查看 GC 情况：

```bash
jstat -gcutil <pid> 1000
```

重点看：

```text
Young GC 是否频繁
Full GC 是否频繁
Full GC 耗时是否过长
老年代是否持续上涨
```

常见原因：

```text
内存泄漏
大对象频繁创建
一次查询数据太多
缓存无限增长
线程池队列堆积大量任务
```

---

## 4. 排查数据库

数据库是接口慢的高频原因。

重点看：

```text
慢 SQL
索引是否命中
连接池是否打满
锁等待
事务是否过长
主从延迟
数据库 CPU / IO 是否高
```

### 4.1 查看慢 SQL

开启或查看慢查询日志：

```sql
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'long_query_time';
```

分析 SQL：

```sql
EXPLAIN SELECT ...
```

重点看：

```text
type 是否为 ALL
key 是否使用索引
rows 扫描行数
Extra 是否有 Using filesort / Using temporary
```

---

### 4.2 常见 SQL 慢原因

```text
没有索引
索引失效
扫描数据量太大
深分页
排序字段没索引
关联表过多
大事务
行锁等待
一次返回大量数据
```

---

### 4.3 数据库连接池是否不够

如果连接池满了，请求会等待连接。

重点看：

```text
active 连接数
idle 连接数
wait 线程数
连接获取耗时
```

常见原因：

```text
慢 SQL 占用连接
事务未及时提交
连接池配置过小
数据库性能瓶颈
```

---

## 5. 排查 Redis

Redis 慢也会拖慢接口。

重点看：

```text
Redis RT
慢查询
大 Key
热 Key
网络耗时
连接池是否打满
```

查看慢查询：

```bash
SLOWLOG GET 10
```

常见问题：

```text
大 Key
HGETALL 大 Hash
SMEMBERS 大 Set
LRANGE 0 -1
KEYS *
Redis CPU 高
Redis 网络带宽打满
缓存穿透导致大量请求打 DB
```

---

## 6. 排查 RPC / HTTP 下游调用

如果接口依赖其他服务，要看下游耗时。

重点看：

```text
Dubbo / Feign / HTTP 调用耗时
超时时间配置
重试次数
下游错误率
下游线程池是否满
下游是否也慢
```

常见问题：

```text
下游服务慢
超时时间过长
失败重试放大流量
连接池不够
没有熔断降级
第三方接口波动
```

建议：

```text
所有远程调用必须设置超时
写接口重试必须保证幂等
下游异常要有熔断降级
```

---

## 7. 排查 MQ

如果接口涉及 MQ，要看：

```text
发送消息是否慢
Broker 是否异常
消息是否积压
消费者是否消费慢
```

常见原因：

```text
Broker 压力大
网络抖动
消息体过大
同步发送等待太久
消费者处理慢
消费线程数不足
```

---

## 8. 排查网关和网络

如果应用内部耗时不高，但用户感知慢，要看：

```text
网关耗时
Nginx 耗时
负载均衡耗时
网络延迟
DNS
带宽
丢包
TLS 握手
```

常见问题：

```text
网关限流排队
网关线程池打满
请求体太大
响应体太大
跨机房调用
网络抖动
```

---

## 9. 排查日志

日志也可能导致接口慢。

常见问题：

```text
同步打印大量日志
日志级别设置为 DEBUG
打印大对象
异常堆栈频繁输出
磁盘 IO 打满
日志框架异步队列堵塞
```

建议：

```text
线上避免大量 DEBUG 日志
大对象不要完整打印
核心链路日志异步化
```

---

## 10. 常见优化方向

| 问题 | 优化方式 |
|---|---|
| SQL 慢 | 加索引、改 SQL、分页优化 |
| 数据库压力大 | 缓存、读写分离、分库分表 |
| Redis 慢 | 拆大 Key、避免慢命令、热点缓存 |
| 下游慢 | 超时、熔断、降级、异步化 |
| CPU 高 | 优化计算逻辑、减少序列化、排查死循环 |
| GC 频繁 | 减少大对象、优化内存、调整 JVM |
| 线程池满 | 调整线程池、隔离线程池、缩短耗时 |
| 锁竞争 | 缩小锁粒度、减少锁内逻辑 |
| 日志慢 | 减少日志、异步日志 |
| 瞬时流量高 | 限流、削峰、MQ 异步 |

---

## 11. 排查顺序推荐

```text
1. 看监控：确认慢接口、慢时间段、影响范围。
2. 看链路：定位慢在应用、DB、Redis、RPC 还是网关。
3. 看日志：确认是否有异常、超时、重试。
4. 看应用：CPU、线程池、GC、锁竞争。
5. 看数据库：慢 SQL、索引、锁、连接池。
6. 看缓存：Redis 慢查询、大 Key、热 Key。
7. 看下游：RPC / HTTP 调用耗时和错误率。
8. 看网络：网关、Nginx、带宽、丢包。
9. 优化后压测验证。
```

---

## 12. 总结

线上接口很慢，不能一上来就改代码，要先定位瓶颈。

我一般会先看监控，确认是单接口慢还是整体服务慢，再通过链路追踪拆分接口耗时，看慢在网关、应用、数据库、Redis、RPC 还是第三方接口。

如果慢在应用层，就排查 CPU、线程池、GC、锁竞争和日志；如果慢在数据库，就看慢 SQL、执行计划、索引、锁等待和连接池；如果慢在 Redis，就看慢命令、大 Key、热 Key 和连接池；如果慢在下游，就看超时、重试、熔断和下游服务状态。

一句话总结：

```text
线上接口慢排查 = 先看监控定范围，再看链路定位置，最后按应用、DB、Redis、RPC、网络逐层定位。
```
