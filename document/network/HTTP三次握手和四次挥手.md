# TCP 三次握手和四次挥手总结

严格来说，**三次握手和四次挥手是 TCP 的机制，不是 HTTP 的机制**。  
HTTP 是应用层协议，底层通常依赖 TCP 建立连接。

---

## 1. 三次握手是什么

三次握手用于 **建立 TCP 连接**。

核心目标：

```text
确认客户端和服务端的发送、接收能力都正常
```

---

## 2. 三次握手流程

```text
客户端                  服务端

SYN
--------------------->

        SYN + ACK
<---------------------

ACK
--------------------->
```

### 第一次握手

客户端发送 `SYN` 给服务端。

```text
客户端告诉服务端：我要建立连接
```

客户端状态：

```text
SYN_SENT
```

---

### 第二次握手

服务端收到 `SYN` 后，返回 `SYN + ACK`。

```text
服务端告诉客户端：
我收到了你的请求
我也准备建立连接
```

服务端状态：

```text
SYN_RECEIVED
```

---

### 第三次握手

客户端收到 `SYN + ACK` 后，返回 `ACK`。

```text
客户端告诉服务端：
我收到了你的确认
连接可以建立了
```

双方进入：

```text
ESTABLISHED
```

---

## 3. 为什么是三次握手，不是两次

如果只有两次握手，服务端无法确认：

```text
客户端是否能正常接收服务端的响应
```

三次握手可以确认：

| 能力 | 如何确认 |
|---|---|
| 客户端发送能力 | 服务端收到 SYN |
| 服务端接收能力 | 服务端收到 SYN |
| 服务端发送能力 | 客户端收到 SYN + ACK |
| 客户端接收能力 | 客户端收到 SYN + ACK |

第三次 ACK 的作用是：

```text
让服务端确认客户端接收能力正常
```

---

## 4. 四次挥手是什么

四次挥手用于 **关闭 TCP 连接**。

TCP 是全双工通信：

```text
客户端到服务端一条通道
服务端到客户端一条通道
```

所以关闭连接时，双方都要分别关闭自己的发送通道。

---

## 5. 四次挥手流程

```text
客户端                  服务端

FIN
--------------------->

        ACK
<---------------------

        FIN
<---------------------

ACK
--------------------->
```

---

### 第一次挥手

客户端发送 `FIN`。

```text
客户端告诉服务端：
我没有数据要发了，准备关闭连接
```

客户端进入：

```text
FIN_WAIT_1
```

---

### 第二次挥手

服务端返回 `ACK`。

```text
服务端告诉客户端：
我知道你要关闭了
```

客户端进入：

```text
FIN_WAIT_2
```

服务端进入：

```text
CLOSE_WAIT
```

注意：

```text
此时客户端不能再发数据
但服务端还可以继续发数据
```

---

### 第三次挥手

服务端处理完剩余数据后，发送 `FIN`。

```text
服务端告诉客户端：
我也没有数据要发了，可以关闭了
```

服务端进入：

```text
LAST_ACK
```

---

### 第四次挥手

客户端收到服务端 `FIN` 后，返回 `ACK`。

```text
客户端告诉服务端：
我收到了你的关闭请求
```

客户端进入：

```text
TIME_WAIT
```

等待一段时间后关闭连接。

---

## 6. 为什么挥手需要四次

因为 TCP 是全双工的。

客户端关闭发送通道，不代表服务端也立刻没有数据要发。

所以流程是：

```text
客户端先说：我发完了
服务端确认：我知道了

服务端再说：我也发完了
客户端确认：我知道了
```

简单理解：

```text
双方都要各自关闭一次发送通道
```

---

## 7. TIME_WAIT 是什么

主动关闭连接的一方，在发送最后一个 `ACK` 后，会进入 `TIME_WAIT` 状态。

它不会立刻关闭，而是等待一段时间。

常见等待时间：

```text
2MSL
```

---

## 8. 为什么需要 TIME_WAIT

### 1. 确保最后一个 ACK 能到达服务端

如果最后一个 `ACK` 丢失，服务端会重发 `FIN`。

客户端还在 `TIME_WAIT` 状态，就可以重新发送 `ACK`。

---

### 2. 防止旧连接的数据影响新连接

等待一段时间，可以让网络中旧连接的残留报文自然失效。

避免：

```text
旧连接的数据包
被新连接误认为有效数据
```

---

## 9. 三次握手和四次挥手对比

| 对比项 | 三次握手 | 四次挥手 |
|---|---|---|
| 作用 | 建立连接 | 关闭连接 |
| 核心报文 | SYN、ACK | FIN、ACK |
| 次数 | 3 次 | 4 次 |
| 原因 | 确认双方收发能力 | 双方分别关闭发送通道 |
| 常见状态 | SYN_SENT、ESTABLISHED | FIN_WAIT、CLOSE_WAIT、TIME_WAIT |

---

## 10. 总结

三次握手是 TCP 建立连接的过程，客户端先发送 `SYN`，服务端返回 `SYN + ACK`，客户端再返回 `ACK`。三次握手的目的是确认客户端和服务端的发送、接收能力都正常。

四次挥手是 TCP 关闭连接的过程。由于 TCP 是全双工通信，客户端和服务端都需要分别关闭自己的发送通道，所以需要四次挥手。

主动关闭连接的一方会进入 `TIME_WAIT` 状态，用于保证最后一个 `ACK` 能被对方收到，同时防止旧连接的残留报文影响新连接。

一句话总结：

```text
三次握手 = 建立连接，确认双方收发能力；
四次挥手 = 关闭连接，双方分别关闭发送通道。
```
