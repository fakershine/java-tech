# TCP 协议总结

TCP 是传输层协议，全称：

```text
Transmission Control Protocol
```

核心特点：

```text
面向连接
可靠传输
字节流协议
全双工通信
有序传输
流量控制
拥塞控制
```

---

## 1. TCP 在网络模型中的位置

```text
应用层：HTTP、HTTPS、FTP、SMTP
传输层：TCP、UDP
网络层：IP
数据链路层：以太网、Wi-Fi
```

TCP 负责：

```text
端到端的数据可靠传输
```

---

## 2. TCP 的核心特点

| 特点 | 说明 |
|---|---|
| 面向连接 | 传输数据前需要先建立连接 |
| 可靠传输 | 保证数据不丢、不重、不乱序 |
| 字节流 | 没有消息边界，传输的是连续字节流 |
| 全双工 | 客户端和服务端可以同时收发数据 |
| 有序性 | 按发送顺序交付给应用层 |
| 流量控制 | 防止发送方压垮接收方 |
| 拥塞控制 | 防止发送方压垮网络 |

---

## 3. TCP 和 UDP 区别

| 对比项 | TCP | UDP |
|---|---|---|
| 是否连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不保证可靠 |
| 顺序性 | 保证顺序 | 不保证顺序 |
| 速度 | 相对慢 | 快 |
| 开销 | 较大 | 较小 |
| 传输形式 | 字节流 | 数据报 |
| 典型场景 | HTTP、文件传输、支付 | 直播、游戏、DNS、语音 |

一句话：

```text
TCP 可靠但开销大；
UDP 快但不保证可靠。
```

---

## 4. TCP 三次握手

TCP 建立连接需要三次握手。

```text
客户端                  服务端

SYN
--------------------->

        SYN + ACK
<---------------------

ACK
--------------------->
```

### 第一次握手

```text
客户端发送 SYN，请求建立连接
```

### 第二次握手

```text
服务端返回 SYN + ACK，表示收到请求并同意连接
```

### 第三次握手

```text
客户端返回 ACK，连接建立成功
```

目的：

```text
确认双方发送和接收能力都正常
```

---

## 5. 为什么是三次握手

三次握手可以确认：

```text
客户端发送能力正常
客户端接收能力正常
服务端发送能力正常
服务端接收能力正常
```

如果只有两次，服务端无法确认：

```text
客户端是否能收到服务端响应
```

---

## 6. TCP 四次挥手

TCP 关闭连接需要四次挥手。

```text
客户端                  服务端

FIN
--------------------->

        ACK
<---------------------

        FIN
<---------------------

ACK
--------------------->
```

原因：

```text
TCP 是全双工通信
双方都要分别关闭自己的发送通道
```

---

## 7. TIME_WAIT

主动关闭连接的一方会进入：

```text
TIME_WAIT
```

作用：

```text
确保最后一个 ACK 能到达对方
防止旧连接残留报文影响新连接
```

等待时间通常是：

```text
2MSL
```

---

## 8. TCP 如何保证可靠传输

TCP 可靠性主要靠：

```text
序列号
确认应答 ACK
超时重传
快速重传
滑动窗口
流量控制
拥塞控制
校验和
```

---

## 9. 序列号

TCP 会给每个字节编号。

```text
发送方发送数据时带上序列号
接收方根据序列号判断顺序
```

作用：

```text
保证有序
去重
判断是否丢包
```

---

## 10. ACK 确认应答

接收方收到数据后，会返回 ACK。

```text
发送方发送 seq=100 的数据
接收方收到后返回 ack=101
```

含义：

```text
101 之前的数据我都收到了，下一次希望收到 101
```

---

## 11. 超时重传

发送方发送数据后，会启动定时器。

```text
如果超时还没收到 ACK
  ↓
认为数据丢失
  ↓
重新发送
```

这就是超时重传。

---

## 12. 快速重传

如果接收方发现中间缺了一段数据，会重复发送相同 ACK。

例如：

```text
收到 1、2、4、5
缺少 3
```

接收方会重复 ACK：

```text
ack = 3
```

发送方连续收到多个重复 ACK 后，会认为数据 3 丢失，立即重传。

```text
不必等超时
```

---

## 13. 滑动窗口

如果每发送一个包都等 ACK，效率很低。

滑动窗口允许：

```text
一次发送多个数据包
不必每个包都等待 ACK 后再发
```

示意：

```text
窗口内的数据可以连续发送
收到 ACK 后窗口向前滑动
```

作用：

```text
提升传输效率
```

---

## 14. 流量控制

流量控制解决：

```text
发送方不要把接收方缓冲区打满
```

接收方会通过 TCP 头部中的：

```text
窗口大小 window
```

告诉发送方自己还能接收多少数据。

```text
接收方窗口大：发送方多发
接收方窗口小：发送方少发
接收方窗口为 0：发送方暂停发送
```

---

## 15. 拥塞控制

拥塞控制解决：

```text
发送方不要把网络打爆
```

核心算法：

```text
慢启动
拥塞避免
快速重传
快速恢复
```

---

## 16. 慢启动

连接刚开始时，不知道网络承载能力。

所以 TCP 会从小窗口开始发送：

```text
拥塞窗口 cwnd 从小变大
```

增长方式：

```text
指数增长
```

直到达到阈值。

---

## 17. 拥塞避免

当窗口达到阈值后，增长速度变慢。

```text
从指数增长变成线性增长
```

避免网络突然被打满。

---

## 18. 快速恢复

如果发生丢包，TCP 会认为网络可能拥塞。

处理方式：

```text
降低拥塞窗口
进入快速恢复
继续谨慎发送
```

---

## 19. TCP 粘包和拆包

TCP 是字节流协议，没有消息边界。

所以可能出现：

```text
多个小包被合并成一个包：粘包
一个大包被拆成多个包：拆包
```

例如发送：

```text
hello
world
```

接收方可能收到：

```text
helloworld
```

也可能收到：

```text
hel
loworld
```

---

## 20. 粘包拆包解决方案

常见方案：

| 方案 | 说明 |
|---|---|
| 固定长度 | 每个消息固定长度 |
| 分隔符 | 用特殊符号分隔消息 |
| 消息头 + 消息体 | 消息头中记录消息长度 |
| 协议编码器 | Netty 编解码器处理 |

最常用：

```text
消息头记录 body 长度
```

---

## 21. TCP 常见状态

| 状态 | 说明 |
|---|---|
| LISTEN | 服务端监听连接 |
| SYN_SENT | 客户端发送 SYN 后等待响应 |
| SYN_RECEIVED | 服务端收到 SYN 并返回 SYN+ACK |
| ESTABLISHED | 连接已建立 |
| FIN_WAIT_1 | 主动关闭方发送 FIN |
| FIN_WAIT_2 | 主动关闭方等待对方 FIN |
| CLOSE_WAIT | 被动关闭方收到 FIN |
| LAST_ACK | 被动关闭方发送 FIN 后等待 ACK |
| TIME_WAIT | 主动关闭方等待旧报文失效 |
| CLOSED | 连接关闭 |

---

## 22. TCP 常见问题

### 1. 大量 TIME_WAIT

原因：

```text
主动关闭连接太多
短连接过多
```

解决：

```text
使用连接复用
开启 KeepAlive
优化客户端连接池
减少频繁建连断连
```

---

### 2. 大量 CLOSE_WAIT

原因：

```text
对端关闭连接后，本端没有正确 close
```

通常是应用代码问题。

解决：

```text
检查连接释放逻辑
检查 HTTP client / socket 是否关闭
检查连接池配置
```

---

### 3. 连接超时

可能原因：

```text
网络不通
服务端没监听端口
防火墙拦截
连接队列满
服务端负载高
```

---

## 23. TCP 和 HTTP 的关系

```text
TCP 是传输层协议
HTTP 是应用层协议
HTTP 通常基于 TCP 传输
```

访问网页时：

```text
先建立 TCP 连接
再发送 HTTP 请求
```

HTTPS 是：

```text
HTTP + TLS + TCP
```

---

## 24. 总结

TCP 是面向连接、可靠的传输层协议。它通过三次握手建立连接，通过四次挥手关闭连接。

TCP 通过序列号、ACK 确认、超时重传、快速重传、滑动窗口、流量控制和拥塞控制来保证可靠传输。

TCP 是字节流协议，没有天然消息边界，所以会有粘包和拆包问题，通常通过固定长度、分隔符或消息头长度字段解决。

一句话总结：

```text
TCP = 面向连接 + 可靠传输 + 字节流；
可靠性靠序列号、ACK、重传、滑动窗口、流量控制和拥塞控制。
```
