# 跨域总结

跨域是指：**浏览器限制网页向不同源的服务器发送请求或读取响应**。

跨域问题本质是浏览器的 **同源策略** 导致的。

---

## 1. 什么是同源策略

同源要求三个部分完全相同：

```text
协议相同
域名相同
端口相同
```

示例：

```text
http://www.demo.com:8080
```

只要以下任意一个不同，就是跨域：

| URL | 是否同源 | 原因 |
|---|---|---|
| `https://www.demo.com:8080` | 否 | 协议不同 |
| `http://api.demo.com:8080` | 否 | 域名不同 |
| `http://www.demo.com:9090` | 否 | 端口不同 |

---

## 2. 为什么浏览器要限制跨域

主要是为了安全，防止恶意网站读取用户在其他网站的数据。

例如：

```text
用户登录了银行网站
  ↓
又打开恶意网站
  ↓
恶意网站偷偷请求银行接口
  ↓
如果没有同源策略，恶意网站可能读取银行数据
```

所以浏览器默认限制跨域响应读取。

---

## 3. 跨域发生在哪里

跨域限制发生在：

```text
浏览器
```

不是服务器限制，也不是 HTTP 协议限制。

也就是说：

```text
服务端之间调用不存在浏览器跨域问题
Postman 调接口通常也没有跨域问题
```

---

## 4. 常见跨域场景

```text
前端 localhost:3000
后端 localhost:8080
```

虽然都是 localhost，但端口不同，所以跨域。

```text
前端 www.demo.com
后端 api.demo.com
```

域名不同，也跨域。

---

## 5. CORS 解决跨域

CORS 是最常见的跨域解决方案。

全称：

```text
Cross-Origin Resource Sharing
```

核心思想：

```text
服务端在响应头中告诉浏览器：
允许哪些来源访问当前资源。
```

常见响应头：

```http
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS
Access-Control-Allow-Headers: Content-Type,Authorization
Access-Control-Allow-Credentials: true
```

---

## 6. 简单请求和预检请求

浏览器跨域请求分为：

```text
简单请求
非简单请求
```

---

### 简单请求

满足一定条件时，浏览器会直接发送真实请求。

常见简单请求：

```text
GET
POST
HEAD
```

并且请求头和 Content-Type 也有限制。

---

### 预检请求

如果是非简单请求，浏览器会先发送一个：

```text
OPTIONS 请求
```

也叫预检请求。

流程：

```text
浏览器先发 OPTIONS
  ↓
服务端返回允许跨域的响应头
  ↓
浏览器确认允许
  ↓
再发送真实请求
```

常见触发预检的情况：

```text
PUT / DELETE 请求
携带 Authorization 请求头
Content-Type 是 application/json
自定义 Header
```

---

## 7. 后端配置 CORS

### Spring Boot 全局配置

```java
@Configuration
public class CorsConfig {

    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {

            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/**")
                        .allowedOriginPatterns("*")
                        .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                        .allowedHeaders("*")
                        .allowCredentials(true)
                        .maxAge(3600);
            }
        };
    }
}
```

注意：

```text
如果 allowCredentials(true)，Access-Control-Allow-Origin 不能直接配置为 *
```

需要指定具体域名，或使用 `allowedOriginPatterns`。

---

### Controller 局部配置

```java
@CrossOrigin(origins = "http://localhost:3000")
@RestController
public class UserController {

    @GetMapping("/user")
    public String user() {
        return "ok";
    }
}
```

## 8. 网关解决跨域

在微服务中，通常推荐在网关统一处理跨域。

```text
前端
  ↓
网关统一处理 CORS
  ↓
后端微服务
```

好处：

```text
不用每个服务重复配置
统一管理跨域规则
减少配置冲突
```

---

## 9. Nginx 解决跨域

可以在 Nginx 中添加响应头：

```nginx
add_header Access-Control-Allow-Origin $http_origin;
add_header Access-Control-Allow-Methods 'GET, POST, PUT, DELETE, OPTIONS';
add_header Access-Control-Allow-Headers 'Content-Type, Authorization';
add_header Access-Control-Allow-Credentials true;

if ($request_method = OPTIONS) {
    return 204;
}
```

适合：

```text
前端和后端通过 Nginx 统一代理
```

---

## 10. 代理解决跨域

开发环境常用前端代理。

例如 Vue / Vite / Webpack devServer：

```text
前端请求 /api/user
  ↓
前端开发服务器代理到 http://localhost:8080/user
```

浏览器看到的是：

```text
localhost:3000/api/user
```

所以对浏览器来说是同源请求。

---

## 11. JSONP

JSONP 是早期跨域方案，只支持 GET。

原理：

```text
script 标签不受同源策略限制
```

示例：

```html
<script src="https://api.demo.com/user?callback=handle"></script>
```

缺点：

```text
只支持 GET
安全性差
现在使用较少
```

---

## 12. 跨域和 Cookie

如果跨域请求需要携带 Cookie：

前端需要配置：

```javascript
axios.defaults.withCredentials = true;
```

服务端需要配置：

```http
Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: 具体域名
```

不能是：

```http
Access-Control-Allow-Origin: *
```

---

## 13. 常见解决方案对比

| 方案 | 说明 | 适用场景 |
|---|---|---|
| CORS | 服务端设置跨域响应头 | 最常用 |
| 网关统一跨域 | 网关处理 CORS | 微服务 |
| Nginx 跨域 | 反向代理加响应头 | 前后端部署 |
| 前端代理 | 开发环境代理请求 | 本地开发 |
| JSONP | script 标签跨域 | 老系统，只支持 GET |

---

## 14. 常见问题

### 1. 为什么 Postman 可以，浏览器不行？

因为跨域是浏览器同源策略限制。

```text
Postman 不受浏览器同源策略限制
```

---

### 2. 为什么有时候会先发 OPTIONS？

因为浏览器判断这是非简单请求，会先发送预检请求。

---

### 3. 为什么配置了 `*` 还不能带 Cookie？

因为浏览器安全限制：

```text
携带凭证时，Access-Control-Allow-Origin 不能是 *
```

必须是具体 Origin。

---

### 4. 跨域是前端问题还是后端问题？

本质是浏览器安全策略问题。

解决通常需要：

```text
后端 / 网关 / Nginx 返回正确 CORS 响应头
```

---

## 15. 总结

跨域是浏览器同源策略导致的问题。同源要求协议、域名、端口完全一致，只要其中一个不同，就属于跨域。

跨域限制只存在于浏览器环境，服务端调用服务端、Postman 调接口一般不存在跨域问题。

最常见的解决方案是 CORS，也就是服务端通过响应头告诉浏览器允许哪些来源访问资源。对于非简单请求，浏览器会先发送 OPTIONS 预检请求，服务端允许后才会发送真实请求。

实际项目中，单体应用可以在后端配置 CORS；微服务架构一般推荐在网关统一处理跨域；开发环境也可以通过前端代理解决跨域。

一句话总结：

```text
跨域 = 浏览器同源策略限制；
解决核心 = 服务端或网关返回正确的 CORS 响应头。
```
