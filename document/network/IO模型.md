# IO 模型总结

IO 模型主要描述的是：**线程在等待数据、读取数据时，是阻塞还是非阻塞，是同步还是异步**。

常见 IO 模型有五种：

```text
阻塞 IO
非阻塞 IO
IO 多路复用
信号驱动 IO
异步 IO
```

---

## 1. IO 操作的两个阶段

一次网络 IO 通常分为两个阶段：

```text
1. 等待数据准备好
2. 将数据从内核空间拷贝到用户空间
```

例如读取 Socket 数据：

```text
网卡收到数据
  ↓
数据进入内核缓冲区
  ↓
应用程序从内核缓冲区读取数据
```

---

## 2. 阻塞 IO

### 实现原理

线程发起 IO 请求后，如果数据没有准备好，线程会一直阻塞。

```text
线程调用 read()
  ↓
数据未准备好
  ↓
线程阻塞等待
  ↓
数据准备好
  ↓
拷贝数据
  ↓
read() 返回
```

### 优势

- 编程简单。
- 逻辑清晰。

### 劣势

- 一个连接通常占用一个线程。
- 并发高时线程数量多。
- 线程切换和内存开销大。

### 适用场景

```text
连接数少
并发不高
简单应用
```

---

## 3. 非阻塞 IO

### 实现原理

线程发起 IO 请求后，如果数据没准备好，方法不会阻塞，而是立即返回。

```text
线程调用 read()
  ↓
数据未准备好
  ↓
立即返回
  ↓
线程不断轮询
  ↓
数据准备好后读取
```

### 优势

- 线程不会一直阻塞。
- 可以处理多个连接。

### 劣势

- 需要不断轮询。
- CPU 空转浪费严重。
- 编程复杂度更高。

### 适用场景

```text
低延迟要求
少量连接轮询
```

---

## 4. IO 多路复用

### 实现原理

一个线程可以监听多个连接，当某个连接就绪后，再处理对应 IO。

```text
多个 Socket 注册到 Selector
  ↓
线程阻塞在 select()
  ↓
某些 Socket 就绪
  ↓
返回就绪事件
  ↓
线程处理读写
```

常见实现：

```text
select
poll
epoll
kqueue
```

### 优势

- 一个线程可以处理大量连接。
- 减少线程数量。
- 适合高并发网络服务。

### 劣势

- 编程模型复杂。
- IO 数据拷贝阶段仍然是同步的。
- 业务处理不能阻塞 IO 线程。

### 适用场景

```text
高并发连接
网关
RPC 框架
Redis
Nginx
Netty
```

---

## 5. 信号驱动 IO

### 实现原理

应用程序注册信号处理函数，数据准备好后，内核通过信号通知应用程序。

```text
注册信号处理器
  ↓
数据准备好
  ↓
内核发送信号
  ↓
应用程序收到信号
  ↓
调用 read() 读取数据
```

### 优势

- 等待数据期间线程不阻塞。
- 不需要频繁轮询。

### 劣势

- 信号处理复杂。
- 实际项目中使用较少。
- 对网络编程支持不如 IO 多路复用常见。

### 适用场景

```text
较少用于常规 Java 服务开发
```

---

## 6. 异步 IO

### 实现原理

应用程序发起 IO 请求后立即返回，内核负责等待数据和数据拷贝，完成后通知应用程序。

```text
应用发起 read()
  ↓
立即返回
  ↓
内核等待数据
  ↓
内核完成数据拷贝
  ↓
通知应用程序处理结果
```

### 优势

- 等待数据不阻塞。
- 数据拷贝也不阻塞应用线程。
- 理论上性能和并发能力更好。

### 劣势

- 编程复杂。
- 操作系统支持差异较大。
- Java 中实际使用不如 NIO / Netty 普遍。

### 适用场景

```text
高并发异步服务
对线程资源要求高的场景
```

---

## 7. 五种 IO 模型对比

| IO 模型 | 等待数据 | 数据拷贝 | 特点 |
|---|---|---|---|
| 阻塞 IO | 阻塞 | 阻塞 | 简单，但并发差 |
| 非阻塞 IO | 不阻塞，轮询 | 阻塞 | CPU 空转明显 |
| IO 多路复用 | 阻塞在 Selector | 阻塞 | 一个线程监听多个连接 |
| 信号驱动 IO | 不阻塞，信号通知 | 阻塞 | 使用较少 |
| 异步 IO | 不阻塞 | 不阻塞 | 内核完成后通知 |

---

## 8. 同步 IO 和异步 IO 区别

同步 IO：

```text
数据拷贝阶段需要应用线程参与
```

包括：

```text
阻塞 IO
非阻塞 IO
IO 多路复用
信号驱动 IO
```

异步 IO：

```text
数据等待和数据拷贝都由内核完成
应用线程只接收完成通知
```

---

## 9. Java 中的 IO 模型

| Java 模型 | 对应说明 |
|---|---|
| BIO | Blocking IO，阻塞 IO |
| NIO | Non-blocking IO，基于 Selector 的 IO 多路复用 |
| AIO | Asynchronous IO，异步 IO |

---

## 10. BIO

### 特点

```text
一个连接一个线程
```

流程：

```text
ServerSocket.accept()
  ↓
Socket.read()
  ↓
线程阻塞等待请求
```

适合：

```text
连接数少
并发低
简单服务
```

---

## 11. NIO

### 特点

```text
一个线程可以管理多个连接
```

核心组件：

```text
Channel
Buffer
Selector
SelectionKey
```

流程：

```text
Channel 注册到 Selector
  ↓
Selector 监听事件
  ↓
事件就绪后处理读写
```

适合：

```text
高并发连接
长连接服务
Netty
Redis 客户端
RPC 框架
```

---

## 12. AIO

### 特点

```text
异步非阻塞
```

应用发起 IO 后不需要等待，完成后通过回调通知。

适合：

```text
异步文件 IO
部分高并发异步场景
```

但在 Java 服务端开发中，实际使用频率不如 NIO + Netty。

---

## 13. 总结

IO 模型主要分为阻塞 IO、非阻塞 IO、IO 多路复用、信号驱动 IO 和异步 IO。

阻塞 IO 是一个线程等待一个连接，简单但并发能力差。非阻塞 IO 不会阻塞线程，但需要不断轮询，容易浪费 CPU。IO 多路复用通过 Selector、epoll 等机制，让一个线程监听多个连接，是高并发网络编程中最常用的模型。信号驱动 IO 实际使用较少。异步 IO 则由内核完成数据准备和数据拷贝，应用只接收完成通知。

Java 中 BIO 对应阻塞 IO，NIO 对应 IO 多路复用，AIO 对应异步 IO。

一句话总结：

```text
BIO：一个连接一个线程；
NIO：一个线程监听多个连接；
AIO：内核完成 IO 后通知应用。
```
