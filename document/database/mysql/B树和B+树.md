# B 树和 B+ 树总结

B 树和 B+ 树都是 **多路平衡搜索树**，常用于磁盘存储和数据库索引。

核心目标：

```text
降低树高
减少磁盘 IO
提高查询效率
```

---

## 1. 为什么不用普通二叉树

普通二叉树每个节点最多 2 个子节点。

如果数据量很大：

```text
树高很高
查询路径很长
磁盘 IO 次数多
```

而 B 树 / B+ 树是多叉树：

```text
一个节点可以存多个 key
一个节点可以有多个子节点
```

好处：

```text
树更矮
一次磁盘 IO 可以读取更多索引信息
查询效率更高
```

---

## 2. B 树是什么

B 树是一种多路平衡搜索树。

特点：

```text
每个节点可以存多个 key
每个节点可以存数据
所有叶子节点在同一层
节点中的 key 有序
```

结构示例：

```text
        [20 | 40]
       /    |    \
 [1..19] [21..39] [41..60]
```

B 树中：

```text
非叶子节点和叶子节点都可以存数据
```

---

## 3. B+ 树是什么

B+ 树是 B 树的变种，也是数据库索引最常用的数据结构。

特点：

```text
非叶子节点只存 key，不存完整数据
所有数据都存放在叶子节点
叶子节点之间通过链表连接
所有叶子节点在同一层
```

结构示例：

```text
          [20 | 40]
         /    |    \
      [20]  [40]  [60]
       ↓      ↓     ↓
[1..20] -> [21..40] -> [41..60]
```

---

## 4. B 树和 B+ 树区别

| 对比项 | B 树 | B+ 树 |
|---|---|---|
| 数据存储位置 | 非叶子节点和叶子节点都存数据 | 只有叶子节点存数据 |
| 非叶子节点 | 存 key + data | 只存 key |
| 叶子节点 | 不一定有链表 | 叶子节点之间有链表 |
| 查询路径 | 可能在非叶子节点命中 | 最终都要到叶子节点 |
| 范围查询 | 不方便 | 非常方便 |
| 树高 | 相对更高 | 通常更低 |
| 磁盘 IO | 相对更多 | 更少 |
| 数据库索引 | 使用较少 | 使用更多 |

---

## 5. 为什么数据库更喜欢 B+ 树

### 1. 非叶子节点能存更多 key

B+ 树非叶子节点只存索引 key，不存完整数据。

所以同样大小的数据页中：

```text
B+ 树能存更多 key
```

结果：

```text
分叉更多
树更矮
磁盘 IO 更少
```

---

### 2. 范围查询效率高

B+ 树叶子节点之间有链表。

范围查询：

```sql
WHERE id BETWEEN 100 AND 200
```

只需要：

```text
先定位到 id=100 的叶子节点
然后沿着叶子节点链表向后扫描
```

非常适合数据库范围查询。

---

### 3. 查询性能更稳定

B 树可能在非叶子节点就查到数据，也可能查到叶子节点。

```text
不同 key 查询路径可能不同
```

B+ 树所有数据都在叶子节点。

```text
每次查询路径长度基本一致
```

所以查询性能更稳定。

---

### 4. 更适合磁盘预读

B+ 树叶子节点顺序连接，范围扫描时可以顺序读取。

```text
顺序 IO 比随机 IO 更快
```

更适合数据库和磁盘存储。

---

## 6. MySQL InnoDB 为什么用 B+ 树

InnoDB 使用 B+ 树作为索引结构。

原因：

```text
树高低，磁盘 IO 少
范围查询效率高
叶子节点链表适合排序扫描
查询性能稳定
适合页式存储
```

InnoDB 页默认大小：

```text
16KB
```

一个索引节点通常就是一个数据页。

```text
一次磁盘 IO 读取一页
一页中存放多个索引 key
```

---

## 7. 聚簇索引和二级索引

### 聚簇索引

InnoDB 主键索引是聚簇索引。

```text
叶子节点存完整行数据
```

结构：

```text
主键 B+ 树
  ↓
叶子节点 = 整行数据
```

---

### 二级索引

普通索引是二级索引。

```text
叶子节点存索引字段 + 主键值
```

查询普通索引时：

```text
先查二级索引
  ↓
拿到主键 ID
  ↓
再回表查聚簇索引
```

---

## 8. 为什么不用 Hash 索引

Hash 索引查询单个值很快：

```text
等值查询 O(1)
```

但缺点明显：

```text
不支持范围查询
不支持排序
不支持最左前缀匹配
Hash 冲突需要处理
```

数据库常见查询包括：

```sql
WHERE id > 100
ORDER BY create_time
WHERE name LIKE 'abc%'
```

这些更适合 B+ 树。

---

## 9. 为什么不用红黑树

红黑树是二叉树，每个节点最多两个子节点。

数据量大时：

```text
树高较高
磁盘 IO 次数多
```

B+ 树是多路树：

```text
一个节点可以有很多子节点
树高更低
磁盘 IO 更少
```

所以数据库索引更适合 B+ 树，而不是红黑树。

---

## 10. 总结

B 树和 B+ 树都是多路平衡搜索树，核心目的都是降低树高，减少磁盘 IO。

B 树的非叶子节点和叶子节点都可以存数据；B+ 树只有叶子节点存数据，非叶子节点只存索引 key，并且叶子节点之间通过链表连接。

数据库索引更常用 B+ 树，因为 B+ 树非叶子节点可以存更多 key，树高更低，磁盘 IO 更少；同时叶子节点链表非常适合范围查询和排序扫描，查询性能也更稳定。

一句话总结：

```text
B 树：节点既存 key 也存 data；
B+ 树：非叶子节点只存 key，数据都在叶子节点，叶子节点链表连接；
MySQL InnoDB 索引用 B+ 树，因为树矮、IO 少、范围查询快。
```
