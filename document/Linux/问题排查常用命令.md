# Linux / Java 线上问题排查常用命令

## 1. CPU 飙高排查

### 查看系统整体 CPU

```bash
top
```

关注：

```text
%Cpu(s)
load average
PID
%CPU
COMMAND
```

---

### 查看某个进程下线程 CPU

```bash
top -Hp <pid>
```

示例：

```bash
top -Hp 12345
```

---

### 将线程 ID 转成 16 进制

```bash
printf "%x\n" <线程ID>
```

示例：

```bash
printf "%x\n" 12366
```

输出：

```text
304e
```

---

### 导出 Java 线程栈

```bash
jstack <pid> > jstack.log
```

---

### 根据线程 ID 查找线程栈

```bash
grep -n "304e" jstack.log
```

---

### CPU 高排查完整流程

```bash
top
top -Hp <pid>
printf "%x\n" <线程ID>
jstack <pid> > jstack.log
grep -n "<十六进制线程ID>" jstack.log
```

常见原因：

- 死循环
- 正则回溯
- 大量 JSON 序列化
- 大集合遍历
- 频繁 GC
- 加密解密计算
- 线程池任务堆积

---

## 2. 内存高排查

### 查看系统内存

```bash
free -h
```

---

### 查看进程内存占用

```bash
top
```

或者：

```bash
ps aux --sort=-%mem | head
```

---

### 查看 Java 堆内存

```bash
jmap -heap <pid>
```

---

### 查看对象数量和大小

```bash
jmap -histo <pid> | head -50
```

---

### 导出堆快照

```bash
jmap -dump:format=b,file=heap.hprof <pid>
```

示例：

```bash
jmap -dump:format=b,file=/tmp/heap.hprof 12345
```

然后用 MAT、VisualVM、JProfiler 分析。

---

### 内存高排查常用流程

```bash
free -h
top
jmap -heap <pid>
jmap -histo <pid> | head -50
jmap -dump:format=b,file=heap.hprof <pid>
```

常见原因：

- 大对象未释放
- 缓存无限增长
- 集合对象过多
- 线程过多
- 堆外内存泄漏
- Full GC 频繁
- 文件流、连接未关闭

---


---

```bash
jcmd <pid> VM.flags
```

或者：

```bash
jinfo -flags <pid>
```

---

### 查看堆内存使用

---

## 4. GC 问题排查

### 查看 GC 情况

```bash
jstat -gc <pid> 1000
```

表示每 1 秒输出一次。

---

### 查看 GC 容量

```bash
jstat -gccapacity <pid> 1000
```

---

### 查看 GC 次数和耗时

```bash
jstat -gcutil <pid> 1000
```

重点关注：

| 字段 | 说明 |
|---|---|
| `S0` | Survivor 0 使用率 |
| `S1` | Survivor 1 使用率 |
| `E` | Eden 区使用率 |
| `O` | 老年代使用率 |
| `M` | 元空间使用率 |
| `YGC` | Young GC 次数 |
| `YGCT` | Young GC 总耗时 |
| `FGC` | Full GC 次数 |
| `FGCT` | Full GC 总耗时 |
| `GCT` | GC 总耗时 |

---

### 查看 GC 日志

```bash
grep -i "Full GC" gc.log
```

```bash
grep -i "Pause" gc.log
```

---

### 常见 GC 问题

- Young GC 频繁
- Full GC 频繁
- 老年代持续上涨
- 大对象直接进入老年代
- 内存泄漏
- 元空间溢出
- 堆设置过小

---

## 5. 磁盘空间排查

### 查看磁盘使用情况

```bash
df -h
```

---

### 查看当前目录文件大小

```bash
du -sh *
```

---

### 按大小排序

```bash
du -sh * | sort -h
```

---

### 查找大文件

```bash
find / -type f -size +1G
```

---

### 查找大日志文件

```bash
find /var/log -type f -size +500M
```

---

### 删除 30 天前日志

```bash
find /data/logs -type f -name "*.log" -mtime +30 -delete
```

---

### 查看已删除但仍被进程占用的文件

```bash
lsof | grep deleted
```

如果日志文件被删除但进程未释放，磁盘空间可能不会立即恢复。

## 6. 磁盘 IO 排查

### 查看 IO 情况

```bash
iostat -x 1
```

重点关注：

| 字段 | 说明 |
|---|---|
| `%util` | 磁盘繁忙程度 |
| `await` | IO 平均等待时间 |
| `r/s` | 每秒读次数 |
| `w/s` | 每秒写次数 |
| `rkB/s` | 每秒读取 KB |
| `wkB/s` | 每秒写入 KB |

---

### 查看哪个进程 IO 高

```bash
iotop
```

如果没有安装：

```bash
yum install iotop
```

或：

```bash
apt install iotop
```

---

### 查看进程 IO

```bash
pidstat -d 1
```

---

---

### 测试网络连通性

```bash

```

或者：


---

```bash

```

---

### 查看响应头

```bash

```

---

### 查看完整请求耗时

```bash
curl -o /dev/null -s -w "%{time_connect} %{time_starttransfer} %{time_total}\n" http://localhost:8080
```

说明：

| 指标 | 含义 |
|---|---|
| `time_connect` | 建立 TCP 连接耗时 |
| `time_starttransfer` | 首字节返回耗时 |
| `time_total` | 总耗时 |

## 9. 线程排查

```bash

```

---

### 查看线程详情

```bash

```

---

### 查看线程 CPU

```bash

```

---

### 导出线程栈

```bash

```

---

### 死锁检测

```bash
jstack <pid> | grep -i deadlock -A 20
```

---

常见线程问题：

- 死锁
- 线程池耗尽
- 大量 WAITING
- 大量 BLOCKED
- 大量 TIMED_WAITING
- 线程数过多
- CPU 线程长时间 RUNNABLE

## 18. 线上排查常用组合

### CPU 高

```bash
top
top -Hp <pid>
printf "%x\n" <tid>
jstack <pid> > jstack.log
grep "<hex_tid>" jstack.log
```

---

### 内存高

```bash
free -h
top
jmap -heap <pid>
jmap -histo <pid> | head -50
jmap -dump:format=b,file=heap.hprof <pid>
```

---

### 磁盘满

```bash
df -h
du -sh /*
du -sh * | sort -h
find / -type f -size +1G
lsof | grep deleted
```

---

### 接口超时

```bash
curl -o /dev/null -s -w "%{time_connect} %{time_starttransfer} %{time_total}\n" http://host/api
grep -E "timeout|ERROR|Exception" app.log
jstack <pid> > jstack.log
```

---

### 端口不通

```bash
ping <host>
nc -vz <host> <port>
ss -tunlp | grep <port>
firewall-cmd --list-ports
```

---

### Java 服务无响应

```bash
ps -ef | grep java
top -Hp <pid>
jstack <pid> > jstack.log
jstat -gcutil <pid> 1000
curl http://localhost:<port>/actuator/health
```

## 19. 常用命令速查表

| 问题 | 常用命令 |
|---|---|
| CPU 高 | `top`、`top -Hp`、`jstack` |
| 内存高 | `free -h`、`jmap -heap`、`jmap -histo` |
| OOM | `grep OutOfMemoryError`、`jmap -dump` |
| GC 频繁 | `jstat -gcutil`、GC 日志 |
| 磁盘满 | `df -h`、`du -sh *`、`find -size` |
| IO 高 | `iostat -x 1`、`iotop` |
| 端口占用 | `lsof -i:端口`、`ss -tunlp` |
| 网络不通 | `ping`、`telnet`、`nc`、`curl` |
| 日志异常 | `tail`、`grep`、`sed`、`awk` |
| MySQL 慢 | `show processlist`、`explain` |
| Redis 慢 | `slowlog get`、`info`、`--bigkeys` |
| 服务状态 | `systemctl status`、`journalctl -u` |

---

## 20. 一句话总结

> 线上问题排查一般先看现象，再按 CPU、内存、GC、磁盘、IO、网络、日志、数据库、缓存、线程栈这几个方向定位；Java 服务排查中最常用的是 `top`、`top -Hp`、`jstack`、`jstat`、`jmap`、`grep`、`tail`、`df`、`du`、`ss`、`lsof`。
