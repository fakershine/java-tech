# 服务治理有哪些方式

服务治理的核心目标：**让微服务在高并发、复杂调用、频繁发布和故障场景下稳定、可控、可观测地运行。**

---

## 1. 服务注册与发现

**作用：** 解决服务地址动态变化问题。

常见组件：

- Nacos
- Eureka
- Consul
- Zookeeper
- Kubernetes Service

---

## 2. 负载均衡

**作用：** 将请求合理分发到多个服务实例。

常见策略：

- 轮询
- 随机
- 权重
- 最少连接
- 一致性 Hash

---

## 3. 健康检查

**作用：** 自动识别不可用实例，避免流量打到异常服务。

常见方式：

- 心跳检测
- HTTP 探活
- TCP 探活
- `/actuator/health`
- Kubernetes `livenessProbe` / `readinessProbe`

---

## 4. 超时控制

**作用：** 防止服务调用长时间阻塞。

常见超时：

- HTTP 连接超时
- HTTP 读取超时
- RPC 调用超时
- 数据库查询超时
- Redis 调用超时

---

## 5. 重试机制

**作用：** 解决短暂网络抖动或瞬时失败。

注意：

- 查询接口可以适当重试
- 写接口必须保证幂等
- 不要盲目重试，避免请求放大

---

## 6. 限流

**作用：** 防止突发流量打垮系统。

常见算法：

- 固定窗口
- 滑动窗口
- 漏桶算法
- 令牌桶算法

常见组件：

- Sentinel
- Resilience4j
- Guava RateLimiter
- Nginx
- Redis + Lua

---

## 7. 熔断

**作用：** 下游异常时，快速失败，防止故障扩散。

熔断状态：

- Closed：正常调用
- Open：直接失败或降级
- Half-Open：少量请求试探恢复

---

## 8. 降级

**作用：** 牺牲非核心功能，保障核心链路可用。

常见方式：

- 返回默认值
- 返回缓存数据
- 返回空结果
- 关闭非核心功能
- 提示系统繁忙

---

## 9. 隔离

**作用：** 防止局部问题影响整个系统。

常见隔离：

- 线程池隔离
- 信号量隔离
- 连接池隔离
- 数据库隔离
- 缓存隔离
- 容器资源隔离

---

## 10. 配置中心

**作用：** 集中管理配置，支持动态变更。

常见组件：

- Nacos Config
- Apollo
- Spring Cloud Config
- Consul KV

常见配置：

- 限流阈值
- 开关配置
- 灰度规则
- 线程池参数
- 数据库配置

---

## 11. 灰度发布

**作用：** 降低新版本上线风险。

常见方式：

- 按用户灰度
- 按 IP 灰度
- 按地区灰度
- 按请求头灰度
- 按流量比例灰度

---

## 12. 服务版本治理

**作用：** 支持新老版本服务并存，避免升级影响调用方。

常见方式：

- 接口版本号
- 服务版本号
- 路由规则
- 向下兼容
- 废弃周期管理

---

## 13. 监控告警

**作用：** 及时发现系统异常。

核心指标：

- QPS
- RT
- P99
- 错误率
- CPU
- 内存
- GC
- 线程池
- 连接池
- MQ 堆积

常见组件：

- Prometheus
- Grafana
- Micrometer
- SkyWalking
- ELK

---

## 14. 链路追踪

**作用：** 定位一次请求在微服务链路中的耗时和异常点。

核心概念：

- TraceId
- SpanId
- ParentSpanId

常见组件：

- SkyWalking
- Zipkin
- Jaeger
- OpenTelemetry

---

## 15. 日志治理

**作用：** 提高问题排查效率，控制日志成本。

常见做法：

- 统一日志格式
- 打印 TraceId
- 日志分级
- 敏感信息脱敏
- 慢 SQL 日志
- 错误日志保留上下文

---

## 16. 安全治理

**作用：** 控制服务访问权限，保护接口安全。

常见方式：

- 认证
- 授权
- Token 校验
- JWT
- OAuth2
- 接口签名
- IP 白名单
- mTLS

---

## 17. 网关治理

**作用：** 作为统一流量入口，集中处理公共能力。

常见功能：

- 路由转发
- 统一鉴权
- 限流
- 黑白名单
- 参数校验
- 灰度路由
- 统一日志
- 跨域处理

常见组件：

- Spring Cloud Gateway
- Kong
- Nginx
- APISIX
- Envoy

---

## 18. 容量治理

**作用：** 明确系统承载能力，提前发现瓶颈。

常见方式：

- 压测
- 容量评估
- 机器扩容
- 线程池调优
- 连接池调优
- 数据库容量评估
- 缓存容量评估

---

## 19. 故障演练

**作用：** 验证系统在异常场景下的可用性。

常见演练：

- 服务宕机
- 数据库故障
- Redis 故障
- MQ 堆积
- 网络延迟
- 接口超时
- 机房故障

---

# 总结

服务治理主要包括：

| 方向 | 手段 |
|---|---|
| 服务发现 | 注册中心、健康检查 |
| 流量治理 | 负载均衡、路由、灰度 |
| 稳定性治理 | 超时、重试、限流、熔断、降级、隔离 |
| 配置治理 | 配置中心、动态刷新、配置回滚 |
| 可观测性 | 日志、监控、链路追踪、告警 |
| 安全治理 | 鉴权、授权、签名、mTLS |
| 发布治理 | 灰度发布、蓝绿发布、回滚 |
| 容量治理 | 压测、扩容、资源隔离 |
| 故障治理 | 故障演练、容灾切换 |

一句话总结：

> 服务治理就是通过注册发现、负载均衡、限流熔断、降级隔离、监控追踪、灰度发布等手段，保障微服务系统稳定运行。
