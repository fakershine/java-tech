# 静态代理和动态代理总结

代理模式的核心是：**不直接访问目标对象，而是通过代理对象访问目标对象，并在调用前后增强功能**。

常见增强功能：

```text
日志
事务
权限校验
监控统计
缓存
远程调用
```

---

## 1. 什么是静态代理

静态代理是指：**代理类在编译期就已经写好**。

目标类和代理类通常实现同一个接口。

### 示例

```java
public interface UserService {
    void save();
}
```

目标类：

```java
public class UserServiceImpl implements UserService {

    @Override
    public void save() {
        System.out.println("保存用户");
    }
}
```

代理类：

```java
public class UserServiceProxy implements UserService {

    private final UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void save() {
        System.out.println("开启事务");
        target.save();
        System.out.println("提交事务");
    }
}
```

使用：

```java
UserService userService = new UserServiceProxy(new UserServiceImpl());
userService.save();
```

---

## 2. 静态代理优缺点

### 优势

- 实现简单。
- 逻辑清晰。
- 编译期就能确定代理关系。
- 不依赖反射，性能较好。

### 劣势

- 每个目标类都要写代理类。
- 代理类数量容易膨胀。
- 代码重复。
- 不够灵活，扩展性差。

---

## 3. 什么是动态代理

动态代理是指：**代理类不是提前写好的，而是在程序运行时动态生成的**。

核心思想：

```text
运行时生成代理对象
  ↓
拦截方法调用
  ↓
执行增强逻辑
  ↓
调用目标方法
```

常见动态代理方式：

```text
JDK 动态代理
CGLIB 动态代理
```

---

## 4. JDK 动态代理

### 实现原理

JDK 动态代理基于接口实现。

要求：

```text
目标类必须实现接口
```

核心类：

```text
Proxy
InvocationHandler
```

### 示例

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

public class JdkProxyFactory {

    public static Object getProxy(Object target) {
        return Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),
                new InvocationHandler() {
                    @Override
                    public Object invoke(Object proxy, Method method, Object[] args)
                            throws Throwable {
                        System.out.println("开启事务");

                        Object result = method.invoke(target, args);

                        System.out.println("提交事务");

                        return result;
                    }
                }
        );
    }
}
```

使用：

```java
UserService userService =
        (UserService) JdkProxyFactory.getProxy(new UserServiceImpl());

userService.save();
```

---

## 5. CGLIB 动态代理

### 实现原理

CGLIB 动态代理基于继承实现。

它会在运行时生成目标类的子类，并重写目标方法实现增强。

要求：

```text
目标类不能是 final
被代理方法不能是 final
```

### 示例

```java
import org.springframework.cglib.proxy.Enhancer;
import org.springframework.cglib.proxy.MethodInterceptor;
import org.springframework.cglib.proxy.MethodProxy;

import java.lang.reflect.Method;

public class CglibProxyFactory {

    public static Object getProxy(Class<?> targetClass) {
        Enhancer enhancer = new Enhancer();

        enhancer.setSuperclass(targetClass);

        enhancer.setCallback(new MethodInterceptor() {
            @Override
            public Object intercept(
                    Object obj,
                    Method method,
                    Object[] args,
                    MethodProxy proxy
            ) throws Throwable {
                System.out.println("开启事务");

                Object result = proxy.invokeSuper(obj, args);

                System.out.println("提交事务");

                return result;
            }
        });

        return enhancer.create();
    }
}
```

使用：

```java
UserServiceImpl userService =
        (UserServiceImpl) CglibProxyFactory.getProxy(UserServiceImpl.class);

userService.save();
```

---

## 6. 静态代理和动态代理区别

| 对比项 | 静态代理 | 动态代理 |
|---|---|---|
| 代理类生成时机 | 编译期手动编写 | 运行期动态生成 |
| 灵活性 | 差 | 强 |
| 代码量 | 多 | 少 |
| 是否需要接口 | 通常需要 | JDK 需要接口，CGLIB 不需要 |
| 性能 | 略好 | 略低，但一般可接受 |
| 维护成本 | 高 | 低 |
| 常见场景 | 简单固定增强 | Spring AOP、RPC、事务 |

---

## 7. JDK 动态代理和 CGLIB 区别

| 对比项 | JDK 动态代理 | CGLIB |
|---|---|---|
| 实现方式 | 基于接口 | 基于继承 |
| 是否需要接口 | 需要 | 不需要 |
| 是否能代理类 | 不能直接代理普通类 | 可以代理普通类 |
| final 类 | 可以代理接口，不代理 final 类 | 不能代理 final 类 |
| final 方法 | 接口方法不受影响 | 不能增强 final 方法 |
| Spring AOP 使用 | 有接口默认用 JDK | 无接口通常用 CGLIB |

---

## 8. Spring AOP 中的代理选择

Spring AOP 默认规则：

```text
目标类实现了接口：默认使用 JDK 动态代理
目标类没有实现接口：使用 CGLIB 动态代理
```

也可以强制使用 CGLIB：

```yaml
spring:
  aop:
    proxy-target-class: true
```

## 9. 典型应用场景

### 1. Spring AOP

```text
@Transactional
@Cacheable
@Async
日志切面
权限校验
```

---

### 2. RPC 框架

Dubbo、Feign 等框架会为接口生成代理对象。

```java
userService.getUser(1L);
```

看起来是本地方法调用，实际上代理对象会发起远程调用。

---

### 3. MyBatis Mapper

MyBatis 的 Mapper 接口没有实现类，本质是通过 JDK 动态代理生成代理对象。

```java
userMapper.selectById(1L);
```

---

## 10. 总结

静态代理是在编译期手动编写代理类，代理类和目标类通常实现同一个接口。优点是简单直观，缺点是每个目标类都要写代理类，代码重复，扩展性差。

动态代理是在运行期动态生成代理对象，可以统一拦截方法调用并进行增强。常见实现有 JDK 动态代理和 CGLIB 动态代理。JDK 动态代理基于接口实现，目标类必须实现接口；CGLIB 基于继承实现，不要求接口，但不能代理 final 类和 final 方法。

Spring AOP、事务、MyBatis Mapper、Dubbo、Feign 等底层都大量使用动态代理。

一句话总结：

```text
静态代理 = 手写代理类；
动态代理 = 运行时生成代理类；
JDK 动态代理基于接口，CGLIB 基于继承。
```
