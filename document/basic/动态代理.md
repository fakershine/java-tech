# 动态代理

## 1. 什么是动态代理

动态代理是指：

> 在程序运行期间，动态生成代理对象，不需要手动编写代理类。

代理对象可以在不修改原始类代码的情况下，对方法调用进行增强。

常见增强逻辑：

```text
日志打印
权限校验
事务控制
性能统计
异常处理
接口限流
远程调用
缓存处理
```

---

## 2. 为什么需要代理

假设有一个业务接口：

```java
public interface UserService {
    void saveUser();
}
```

实现类：

```java
public class UserServiceImpl implements UserService {

    @Override
    public void saveUser() {
        System.out.println("保存用户");
    }
}
```

现在想在 `saveUser()` 执行前后加日志：

```text
方法执行前打印日志
执行原方法
方法执行后打印日志
```

如果直接改业务代码：

```java
public void saveUser() {
    System.out.println("开始执行");
    System.out.println("保存用户");
    System.out.println("执行结束");
}
```

问题是：

```text
业务代码和非业务代码耦合
每个方法都要重复写
不方便统一维护
```

动态代理就是为了解决这类问题。

---

## 3. 代理模式的核心思想

代理模式可以理解为：

> 不直接调用目标对象，而是通过代理对象间接调用目标对象。

调用流程：

```text
调用方
  ↓
代理对象
  ↓
目标对象
```

代理对象可以在调用目标对象前后做增强。

```text
调用方
  ↓
代理对象：前置增强
  ↓
目标对象：执行业务逻辑
  ↓
代理对象：后置增强
```

---

## 4. 静态代理

### 4.1 静态代理示例

接口：

```java
public interface UserService {
    void saveUser();
}
```

目标类：

```java
public class UserServiceImpl implements UserService {

    @Override
    public void saveUser() {
        System.out.println("保存用户");
    }
}
```

代理类：

```java
public class UserServiceProxy implements UserService {

    private final UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void saveUser() {
        System.out.println("方法执行前");
        target.saveUser();
        System.out.println("方法执行后");
    }
}
```

测试：

```java
public class Test {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();
        UserService proxy = new UserServiceProxy(target);

        proxy.saveUser();
    }
}
```

输出：

```text
方法执行前
保存用户
方法执行后
```

---

### 4.2 静态代理缺点

```text
每个接口都要写代理类
方法多时代码重复
维护成本高
不够灵活
```

所以实际开发中更常用动态代理。

---

## 5. 动态代理分类

Java 中常见动态代理方式：

| 类型 | 说明 |
|---|---|
| JDK 动态代理 | 基于接口代理 |
| CGLIB 动态代理 | 基于子类继承代理 |
| Javassist | 字节码增强技术 |
| ByteBuddy | 字节码增强技术，很多框架使用 |

最常见的是：

```text
JDK 动态代理
CGLIB 动态代理
```

# 一、JDK 动态代理

## 6. JDK 动态代理是什么

JDK 动态代理是 Java 原生提供的代理机制。

核心特点：

```text
基于接口
运行时生成代理对象
代理类实现目标接口
通过 InvocationHandler 统一处理方法调用
```

限制：

> JDK 动态代理要求目标类必须实现接口。

---

## 7. JDK 动态代理核心类

| 类 / 接口 | 作用 |
|---|---|
| `Proxy` | 创建代理对象 |
| `InvocationHandler` | 处理代理对象的方法调用 |
| `Method` | 表示被调用的方法 |

核心方法：

```java
Proxy.newProxyInstance(
    ClassLoader loader,
    Class<?>[] interfaces,
    InvocationHandler h
);
```

参数说明：

| 参数 | 说明 |
|---|---|
| `loader` | 类加载器 |
| `interfaces` | 代理对象要实现的接口 |
| `h` | 方法调用处理器 |

---

## 8. JDK 动态代理示例

接口：

```java
public interface UserService {
    void saveUser();

    void deleteUser();
}
```

实现类：

```java
public class UserServiceImpl implements UserService {

    @Override
    public void saveUser() {
        System.out.println("保存用户");
    }

    @Override
    public void deleteUser() {
        System.out.println("删除用户");
    }
}
```

代理处理器：

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;

public class LogInvocationHandler implements InvocationHandler {

    private final Object target;

    public LogInvocationHandler(Object target) {
        this.target = target;
    }

    /**
     * 代理对象调用任何方法，都会进入 invoke 方法。
     */
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("方法执行前：" + method.getName());

        Object result = method.invoke(target, args);

        System.out.println("方法执行后：" + method.getName());

        return result;
    }
}
```

创建代理对象：

```java
import java.lang.reflect.Proxy;

public class Test {
    public static void main(String[] args) {
        UserService target = new UserServiceImpl();

        UserService proxy = (UserService) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),
                new LogInvocationHandler(target)
        );

        proxy.saveUser();
        proxy.deleteUser();
    }
}
```

输出：

```text
方法执行前：saveUser
保存用户
方法执行后：saveUser
方法执行前：deleteUser
删除用户
方法执行后：deleteUser
```

---

## 9. JDK 动态代理调用流程

```text
调用代理对象方法
   ↓
进入 InvocationHandler.invoke()
   ↓
执行前置增强
   ↓
通过 method.invoke(target, args) 调用目标方法
   ↓
执行后置增强
   ↓
返回结果
```

流程图：

```text
UserService proxy
   ↓ saveUser()
InvocationHandler.invoke()
   ↓
method.invoke(target, args)
   ↓
UserServiceImpl.saveUser()
```

---

## 10. JDK 动态代理底层原理

JDK 动态代理底层会在运行期间生成一个代理类。

这个代理类大致长这样：

```java
public final class $Proxy0 extends Proxy implements UserService {

    private InvocationHandler h;

    public $Proxy0(InvocationHandler h) {
        super(h);
        this.h = h;
    }

    @Override
    public void saveUser() {
        h.invoke(this, saveUserMethod, null);
    }

    @Override
    public void deleteUser() {
        h.invoke(this, deleteUserMethod, null);
    }
}
```

所以本质是：

```text
JDK 运行时生成一个实现了目标接口的代理类
代理类的方法统一调用 InvocationHandler.invoke()
```

---

## 11. 保存 JDK 生成的代理类

可以通过参数保存代理类文件：

```java
System.setProperty("sun.misc.ProxyGenerator.saveGeneratedFiles", "true");
```

JDK 8 常用：

```java
System.getProperties().put("sun.misc.ProxyGenerator.saveGeneratedFiles", "true");
```

JDK 9+ 常用：

```java
System.setProperty("jdk.proxy.ProxyGenerator.saveGeneratedFiles", "true");
```

保存后可以看到类似：

```text
$Proxy0.class
```

---

## 12. JDK 动态代理的优缺点

### 优点

```text
JDK 原生支持
不需要额外依赖
实现简单
适合基于接口的代理场景
```

### 缺点

```text
目标类必须实现接口
只能代理接口方法
不能直接代理普通类
反射调用有一定性能开销
```

# 二、CGLIB 动态代理

## 13. CGLIB 动态代理是什么

CGLIB 是一种基于字节码增强的动态代理。

核心特点：

```text
不要求目标类实现接口
通过生成目标类的子类实现代理
通过方法拦截器增强方法
```

简单理解：

> JDK 动态代理是“实现接口”，CGLIB 动态代理是“继承目标类”。

---

## 14. CGLIB 示例

目标类：

```java
public class UserService {

    public void saveUser() {
        System.out.println("保存用户");
    }

    public void deleteUser() {
        System.out.println("删除用户");
    }
}
```

代理类创建：

```java
import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;

import java.lang.reflect.Method;

public class CglibProxyFactory implements MethodInterceptor {

    private final Object target;

    public CglibProxyFactory(Object target) {
        this.target = target;
    }

    public Object getProxy() {
        Enhancer enhancer = new Enhancer();

        // 设置父类
        enhancer.setSuperclass(target.getClass());

        // 设置回调
        enhancer.setCallback(this);

        // 创建代理对象
        return enhancer.create();
    }

    @Override
    public Object intercept(
            Object obj,
            Method method,
            Object[] args,
            MethodProxy proxy
    ) throws Throwable {
        System.out.println("方法执行前：" + method.getName());

        Object result = proxy.invokeSuper(obj, args);

        System.out.println("方法执行后：" + method.getName());

        return result;
    }
}
```

测试：

```java
public class Test {
    public static void main(String[] args) {
        UserService target = new UserService();

        CglibProxyFactory proxyFactory = new CglibProxyFactory(target);

        UserService proxy = (UserService) proxyFactory.getProxy();

        proxy.saveUser();
        proxy.deleteUser();
    }
}
```

输出：

```text
方法执行前：saveUser
保存用户
方法执行后：saveUser
方法执行前：deleteUser
删除用户
方法执行后：deleteUser
```

---

## 15. CGLIB 调用流程

```text
调用代理子类方法
   ↓
进入 MethodInterceptor.intercept()
   ↓
执行前置增强
   ↓
调用父类原方法
   ↓
执行后置增强
   ↓
返回结果
```

---

## 16. CGLIB 底层原理

CGLIB 会在运行时生成目标类的子类。

目标类：

```java
public class UserService {
    public void saveUser() {
        System.out.println("保存用户");
    }
}
```

CGLIB 生成的代理类大致类似：

```java
public class UserService$$EnhancerByCGLIB extends UserService {

    private MethodInterceptor methodInterceptor;

    @Override
    public void saveUser() {
        methodInterceptor.intercept(...);
    }
}
```

所以本质是：

```text
CGLIB 生成目标类的子类
子类重写目标方法
在重写方法中加入增强逻辑
```

---

## 17. CGLIB 的限制

因为 CGLIB 是通过继承实现代理，所以有几个限制：

```text
不能代理 final 类
不能代理 final 方法
不能代理 private 方法
```

原因：

```text
final 类不能被继承
final 方法不能被重写
private 方法子类不可见
```

示例：

```java
public final class UserService {
    public void saveUser() {
        System.out.println("保存用户");
    }
}
```

这种类 CGLIB 无法代理。

---

## 18. CGLIB 优缺点

### 优点

```text
不要求目标类实现接口
可以代理普通类
适合没有接口的类
```

### 缺点

```text
不能代理 final 类
不能代理 final 方法
生成子类有一定成本
需要依赖字节码增强技术
```

---

# 三、JDK 动态代理和 CGLIB 对比

## 19. JDK 代理 vs CGLIB 代理

| 对比项 | JDK 动态代理 | CGLIB 动态代理 |
|---|---|---|
| 实现方式 | 实现接口 | 继承目标类 |
| 是否需要接口 | 需要 | 不需要 |
| 是否能代理普通类 | 不能 | 可以 |
| 是否能代理 final 类 | 不可以 | 不可以 |
| 是否能代理 final 方法 | 接口方法无此问题 | 不可以 |
| 核心类 | `Proxy`、`InvocationHandler` | `Enhancer`、`MethodInterceptor` |
| Spring 默认选择 | 有接口用 JDK | 无接口用 CGLIB |
| 原理 | 运行时生成接口实现类 | 运行时生成目标类子类 |

---

## 20. 简单记忆

```text
JDK 动态代理：基于接口
CGLIB 动态代理：基于继承
```

或者：

```text
有接口：JDK 动态代理
没接口：CGLIB 动态代理
```

# 四、Spring AOP 和动态代理

## 21. Spring AOP 为什么用动态代理

Spring AOP 的核心就是动态代理。

它可以在不修改业务代码的情况下，对方法进行增强。

常见增强：

```text
事务控制
日志打印
权限校验
接口耗时统计
异常处理
缓存控制
```

例如：

```java
@Transactional
public void createOrder() {
    // 创建订单
}
```

`@Transactional` 本质上就是 Spring 通过动态代理在方法前后添加事务逻辑。

---

## 22. Spring AOP 调用流程

```text
调用代理对象方法
   ↓
事务拦截器 / AOP 拦截器
   ↓
开启事务
   ↓
调用目标方法
   ↓
提交事务 / 回滚事务
```

例如：

```text
orderService.createOrder()
   ↓
代理对象
   ↓
TransactionInterceptor
   ↓
开启事务
   ↓
OrderServiceImpl.createOrder()
   ↓
提交事务
```

---

## 23. Spring 选择 JDK 还是 CGLIB

Spring 默认规则：

```text
如果目标类实现了接口，默认使用 JDK 动态代理
如果目标类没有实现接口，使用 CGLIB 动态代理
```

可以强制使用 CGLIB：

```yaml
spring:
  aop:
    proxy-target-class: true
```

或者：

```java
@EnableAspectJAutoProxy(proxyTargetClass = true)
```

---

## 24. Spring 事务失效和动态代理的关系

Spring 事务是通过代理对象实现的。

所以如果没有经过代理对象调用，事务可能失效。

---

### 24.1 同类方法内部调用导致事务失效

示例：

```java
@Service
public class OrderService {

    public void createOrder() {
        this.saveOrder();
    }

    @Transactional
    public void saveOrder() {
        // 保存订单
    }
}
```

问题：

```text
createOrder() 内部通过 this.saveOrder() 调用
没有经过 Spring 代理对象
@Transactional 不生效
```

---

### 24.2 private 方法事务失效

```java
@Transactional
private void saveOrder() {
    // 保存订单
}
```

原因：

```text
private 方法不能被代理增强
```

---

### 24.3 final 方法事务失效

```java
@Transactional
public final void saveOrder() {
    // 保存订单
}
```

原因：

```text
CGLIB 代理需要重写方法
final 方法不能被重写
```

---

## 25. 为什么通过代理对象调用才生效

正常调用：

```text
Controller
   ↓
OrderService 代理对象
   ↓
事务拦截器
   ↓
目标方法
```

内部调用：

```text
目标对象 this.saveOrder()
   ↓
目标方法
```

内部调用绕过了代理对象，所以增强逻辑不会执行。

# 五、MyBatis 和动态代理

## 26. MyBatis Mapper 为什么不用写实现类

MyBatis 中我们通常只写 Mapper 接口：

```java
public interface UserMapper {

    User selectById(Long id);
}
```

但可以直接注入调用：

```java
@Autowired
private UserMapper userMapper;

User user = userMapper.selectById(1L);
```

原因就是：

> MyBatis 为 Mapper 接口生成了动态代理对象。

---

## 27. MyBatis Mapper 动态代理流程

```text
调用 Mapper 接口方法
   ↓
进入 MapperProxy.invoke()
   ↓
根据接口名 + 方法名找到 MappedStatement
   ↓
执行 SQL
   ↓
封装结果
   ↓
返回
```

流程图：

```text
userMapper.selectById(1L)
   ↓
MapperProxy.invoke()
   ↓
SqlSession.selectOne()
   ↓
Executor 执行 SQL
   ↓
返回结果
```

---

## 28. MyBatis 动态代理核心类

| 类 | 作用 |
|---|---|
| `MapperProxy` | Mapper 接口代理处理器 |
| `MapperProxyFactory` | 创建 Mapper 代理对象 |
| `MapperRegistry` | 保存 Mapper 注册信息 |
| `SqlSession` | 执行 SQL |
| `MappedStatement` | 保存 SQL 映射信息 |

userClient.getById(1L);

# 八、动态代理常见面试题

## 33. 什么是动态代理？

动态代理是在程序运行期间动态生成代理对象，通过代理对象拦截方法调用，并在方法调用前后加入增强逻辑。

常见实现方式有 JDK 动态代理和 CGLIB 动态代理。

---

## 34. JDK 动态代理原理是什么？

JDK 动态代理要求目标类实现接口。

JDK 会在运行时生成一个实现了目标接口的代理类，代理类继承 `Proxy`，并持有一个 `InvocationHandler`。

当调用代理对象的方法时，实际会进入 `InvocationHandler.invoke()` 方法，在这个方法中可以执行增强逻辑，并通过反射调用目标对象的方法。

---

## 35. CGLIB 动态代理原理是什么？

CGLIB 动态代理不要求目标类实现接口。

它通过字节码增强技术，在运行时生成目标类的子类，子类重写目标类的方法，并在重写方法中加入增强逻辑。

因为 CGLIB 基于继承，所以不能代理 `final` 类，也不能代理 `final` 方法。

---

## 36. JDK 动态代理和 CGLIB 区别？

| 对比项 | JDK 动态代理 | CGLIB |
|---|---|---|
| 原理 | 实现接口 | 继承目标类 |
| 接口要求 | 必须有接口 | 不需要接口 |
| 代理对象 | 接口实现类 | 目标类子类 |
| 限制 | 只能代理接口方法 | 不能代理 final 类和 final 方法 |
| Spring 使用 | 有接口默认 JDK | 无接口默认 CGLIB |

---

## 37. Spring AOP 用的是哪种代理？

Spring AOP 默认规则：

```text
目标类实现接口：默认使用 JDK 动态代理
目标类没有接口：使用 CGLIB 动态代理
```

也可以通过配置强制使用 CGLIB：

```yaml
spring:
  aop:
    proxy-target-class: true
```

---

## 38. 为什么 Spring 事务会失效？

因为 Spring 事务是基于动态代理实现的。

如果方法调用没有经过代理对象，事务增强就不会执行。

常见事务失效场景：

```text
同类内部方法调用
private 方法
final 方法
方法不是 public
异常被捕获没有抛出
数据库不支持事务
没有被 Spring 管理
```

和动态代理最相关的是：

```text
同类内部调用绕过代理对象
private / final 方法无法被代理增强
```

---

## 39. 动态代理和反射的关系

JDK 动态代理中，代理对象拦截方法后，通常会通过反射调用目标方法：

```java
method.invoke(target, args);
```

所以 JDK 动态代理依赖反射。

CGLIB 主要基于字节码增强和方法拦截，不完全依赖反射调用。

# 九、总结

## 40. 动态代理

动态代理是指在程序运行期间动态生成代理对象，不需要手动编写代理类。通过代理对象可以拦截目标方法调用，在方法执行前后加入日志、事务、权限、监控等增强逻辑。

Java 中常见动态代理有两种：JDK 动态代理和 CGLIB 动态代理。JDK 动态代理基于接口实现，要求目标类必须实现接口。它通过 `Proxy.newProxyInstance()` 创建代理对象，代理对象实现目标接口，并把方法调用交给 `InvocationHandler.invoke()` 处理。

CGLIB 动态代理基于继承实现，不要求目标类实现接口。它通过字节码增强技术生成目标类的子类，并重写目标方法，在方法调用时进入 `MethodInterceptor.intercept()` 实现增强。因为 CGLIB 基于继承，所以不能代理 final 类和 final 方法。

Spring AOP 和 Spring 事务底层就大量使用动态代理。如果目标类有接口，Spring 默认使用 JDK 动态代理；如果没有接口，则使用 CGLIB。像 MyBatis 的 Mapper 接口、Feign 的远程调用接口，也都是动态代理的典型应用。

---

## 41. 一句话总结

> 动态代理的本质是在运行时生成代理对象，通过代理对象拦截方法调用，在不修改目标类代码的情况下完成日志、事务、权限、远程调用等增强逻辑；JDK 动态代理基于接口，CGLIB 动态代理基于继承。
