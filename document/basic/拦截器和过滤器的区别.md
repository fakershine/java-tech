# 拦截器和过滤器总结

过滤器和拦截器都可以对请求做前置、后置处理，常用于：

```text
登录校验
权限控制
日志记录
接口耗时统计
参数校验
跨域处理
请求包装
```

核心区别：

```text
Filter 是 Servlet 规范组件，作用在 Servlet 之前。
Interceptor 是 Spring MVC 组件，作用在 Controller 前后。
```

---

## 1. Filter 过滤器

### 实现原理

Filter 属于 Servlet 规范，作用于 Web 容器层面。

请求进入后，会先经过 Filter，再进入 Servlet。

```text
请求
  ↓
Filter
  ↓
DispatcherServlet
  ↓
Controller
```

### 示例

```java
@Component
public class LoginFilter implements Filter {

    @Override
    public void doFilter(
            ServletRequest request,
            ServletResponse response,
            FilterChain chain
    ) throws IOException, ServletException {

        // 前置处理
        System.out.println("Filter 前置处理");

        chain.doFilter(request, response);

        // 后置处理
        System.out.println("Filter 后置处理");
    }
}
```

---

## 2. Interceptor 拦截器

### 实现原理

Interceptor 属于 Spring MVC，作用于 `DispatcherServlet` 之后、Controller 方法之前。

```text
请求
  ↓
Filter
  ↓
DispatcherServlet
  ↓
Interceptor
  ↓
Controller
```

### 示例

```java
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler
    ) {
        System.out.println("Controller 执行前");
        return true;
    }

    @Override
    public void postHandle(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            ModelAndView modelAndView
    ) {
        System.out.println("Controller 执行后，视图渲染前");
    }

    @Override
    public void afterCompletion(
            HttpServletRequest request,
            HttpServletResponse response,
            Object handler,
            Exception ex
    ) {
        System.out.println("请求完成后");
    }
}
```

注册拦截器：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LoginInterceptor())
                .addPathPatterns("/**")
                .excludePathPatterns("/login");
    }
}
```

---

## 3. 执行顺序

完整流程：

```text
请求进入
  ↓
Filter 前置处理
  ↓
DispatcherServlet
  ↓
Interceptor preHandle
  ↓
Controller
  ↓
Interceptor postHandle
  ↓
视图渲染
  ↓
Interceptor afterCompletion
  ↓
Filter 后置处理
  ↓
响应返回
```

简化理解：

```text
Filter 包在最外层
Interceptor 包在 Controller 外层
```

---

## 4. Filter 和 Interceptor 区别

| 对比项 | Filter | Interceptor |
|---|---|---|
| 所属规范 | Servlet 规范 | Spring MVC |
| 执行位置 | DispatcherServlet 之前 | DispatcherServlet 之后，Controller 前后 |
| 拦截范围 | 几乎所有 Web 请求 | Spring MVC Controller 请求 |
| 是否依赖 Spring | 不一定依赖 | 依赖 Spring MVC |
| 获取 Bean | 原生 Filter 获取 Bean 不如拦截器方便 | 可以方便注入 Spring Bean |
| 粒度 | URL 级别 | Handler / Controller 级别 |
| 典型用途 | 编码、跨域、请求包装、安全过滤 | 登录校验、权限、日志、接口统计 |

---

## 5. 过滤器适合做什么

Filter 更靠近 Web 容器，适合处理底层通用逻辑：

```text
字符编码设置
CORS 跨域处理
请求日志
请求体包装
XSS 防护
Gzip 压缩
安全框架过滤链
```

例如 Spring Security 的核心就是一组 Filter 链。

---

## 6. 拦截器适合做什么

Interceptor 更靠近业务 Controller，适合处理 MVC 相关逻辑：

```text
登录校验
权限判断
接口耗时统计
Controller 访问日志
用户上下文设置
Locale 国际化处理
Handler 级别控制
```

因为它可以拿到 `handler`，知道当前请求要访问哪个 Controller 方法。

---

## 7. 多个 Filter 和 Interceptor 的执行顺序

### 多个 Filter

```text
Filter1 前置
  ↓
Filter2 前置
  ↓
业务逻辑
  ↓
Filter2 后置
  ↓
Filter1 后置
```

类似责任链。

---

### 多个 Interceptor

```text
Interceptor1 preHandle
  ↓
Interceptor2 preHandle
  ↓
Controller
  ↓
Interceptor2 postHandle
  ↓
Interceptor1 postHandle
  ↓
Interceptor2 afterCompletion
  ↓
Interceptor1 afterCompletion
```

注意：

```text
preHandle 按注册顺序执行
postHandle 和 afterCompletion 按反向顺序执行
```

---

## 8. 和 AOP 的区别

| 对比项 | Filter | Interceptor | AOP |
|---|---|---|---|
| 作用层级 | Servlet 层 | Spring MVC 层 | Spring Bean 方法层 |
| 拦截对象 | Web 请求 | Controller 请求 | 任意 Spring Bean 方法 |
| 常见用途 | 请求过滤 | Controller 前后处理 | 业务方法增强 |
| 典型场景 | 跨域、安全、编码 | 登录、权限、日志 | 事务、缓存、审计 |

简单理解：

```text
Filter 拦 Web 请求最外层
Interceptor 拦 Controller
AOP 拦 Spring Bean 方法
```

---

## 9. 常见面试问题

### 1. 登录校验用 Filter 还是 Interceptor？

都可以。

如果是普通业务系统登录校验，推荐：

```text
Interceptor
```

因为它更接近 Controller，方便获取 Spring Bean 和 Handler 信息。

如果是统一安全框架、Token 解析、请求包装，推荐：

```text
Filter
```

---

### 2. 为什么 Filter 能拦截静态资源？

因为 Filter 在 Servlet 容器层面工作，只要 URL 匹配，就可以拦截。

Interceptor 主要拦截 Spring MVC 管理的请求。

---

### 3. Interceptor 能不能拦截异常？

可以在：

```java
afterCompletion()
```

中获取异常对象。

但全局异常处理更推荐使用：

```java
@ControllerAdvice
@ExceptionHandler
```

---

## 10. 总结

Filter 是 Servlet 规范中的过滤器，工作在 Web 容器层面，请求进入 `DispatcherServlet` 之前就会经过 Filter，适合做编码设置、跨域、请求包装、安全过滤等底层通用处理。

Interceptor 是 Spring MVC 提供的拦截器，工作在 `DispatcherServlet` 之后、Controller 方法前后，适合做登录校验、权限判断、接口耗时统计、用户上下文设置等和业务接口相关的处理。

它们都采用责任链思想。Filter 的作用范围更大，Interceptor 更贴近 Spring MVC 和 Controller。

一句话总结：

```text
Filter 是 Servlet 层过滤器，Interceptor 是 Spring MVC 层拦截器；
Filter 更底层，Interceptor 更贴近业务 Controller。
```
