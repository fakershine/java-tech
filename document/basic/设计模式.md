# 设计模式总结

设计模式是对常见软件设计问题的经验总结，核心目标是：**提高代码复用性、扩展性、可维护性，降低耦合度**。

设计模式主要分为三类：

```text
创建型模式
结构型模式
行为型模式
```

---

## 1. 创建型模式

创建型模式主要解决：**对象如何创建**。

| 模式 | 核心思想 | 常见场景 |
|---|---|---|
| 单例模式 | 保证一个类只有一个实例 | 配置类、线程池、Spring Bean |
| 工厂方法模式 | 由子类决定创建哪种对象 | 支付方式、消息发送器 |
| 抽象工厂模式 | 创建一组相关对象 | 多产品族，如不同平台 UI |
| 建造者模式 | 分步骤构建复杂对象 | 构建复杂 DTO、配置对象 |
| 原型模式 | 通过复制已有对象创建新对象 | 对象克隆、模板复制 |

---

## 2. 单例模式

### 实现原理

保证一个类在 JVM 中只有一个实例，并提供全局访问入口。

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 适用场景

- 配置管理。
- 线程池。
- 缓存管理器。
- Spring 默认单例 Bean。

---

## 3. 工厂模式

### 实现原理

把对象创建逻辑封装起来，调用方不直接 `new` 对象。

```java
public class PayFactory {

    public static PayService getPayService(String type) {
        if ("wechat".equals(type)) {
            return new WechatPayService();
        }
        if ("alipay".equals(type)) {
            return new AlipayPayService();
        }
        throw new IllegalArgumentException("不支持的支付方式");
    }
}
```

### 适用场景

- 多种支付方式。
- 多种消息发送方式。
- 多种策略对象创建。

---

## 4. 建造者模式

### 实现原理

用于构建参数较多、创建过程复杂的对象。

```java
User user = User.builder()
        .id(1L)
        .name("Tom")
        .age(18)
        .build();
```

### 适用场景

- DTO 构建。
- 配置对象构建。
- Lombok `@Builder`。

---

## 5. 结构型模式

结构型模式主要解决：**类或对象如何组合**。

| 模式 | 核心思想 | 常见场景 |
|---|---|---|
| 代理模式 | 通过代理对象增强目标对象 | Spring AOP、事务 |
| 装饰器模式 | 动态增强对象功能 | IO 流、Wrapper |
| 适配器模式 | 适配不兼容接口 | Spring MVC HandlerAdapter |
| 门面模式 | 提供统一入口 | Service 封装复杂子系统 |
| 组合模式 | 树形结构统一处理 | 菜单、部门树 |
| 桥接模式 | 抽象和实现分离 | 多维度扩展 |
| 享元模式 | 共享对象减少内存 | 字符串常量池、连接池 |

---

## 6. 代理模式

### 实现原理

代理对象控制对目标对象的访问，并在方法前后做增强。

```text
调用方
  ↓
代理对象
  ↓
目标对象
```

常见实现：

```text
JDK 动态代理
CGLIB 代理
```

### 适用场景

- Spring AOP。
- 事务管理。
- 日志记录。
- 权限校验。
- RPC 远程代理。

---

## 7. 装饰器模式

### 实现原理

在不改变原对象结构的情况下，包装一层增强功能。

```text
原始对象
  ↓
装饰器对象
  ↓
增强功能
```

### 适用场景

- Java IO 流。
- Servlet RequestWrapper。
- 动态增强对象能力。

---

## 8. 适配器模式

### 实现原理

把一个接口转换成调用方期望的另一个接口。

```text
旧接口
  ↓
适配器
  ↓
新接口
```

### 适用场景

- 接入第三方系统。
- 老接口兼容新接口。
- Spring MVC `HandlerAdapter`。

---

## 9. 门面模式

### 实现原理

对外提供统一入口，内部封装多个复杂子系统调用。

```java
public class OrderFacade {

    public void createOrder() {
        userService.checkUser();
        stockService.lockStock();
        orderService.createOrder();
        payService.createPayOrder();
    }
}
```

### 适用场景

- 聚合多个 Service。
- 对外隐藏复杂调用流程。
- 接口层统一封装业务流程。

---

## 10. 行为型模式

行为型模式主要解决：**对象之间如何交互和分配职责**。

| 模式 | 核心思想 | 常见场景 |
|---|---|---|
| 策略模式 | 不同算法可替换 | 支付策略、优惠策略 |
| 模板方法模式 | 固定流程，可变步骤交给子类 | JdbcTemplate |
| 观察者模式 | 事件发布订阅 | Spring 事件、MQ |
| 责任链模式 | 多个处理器链式处理 | Filter、Interceptor |
| 命令模式 | 请求封装成命令对象 | 任务调度、操作记录 |
| 状态模式 | 不同状态不同行为 | 订单状态机 |
| 迭代器模式 | 顺序访问集合元素 | Iterator |
| 中介者模式 | 用中介对象协调交互 | 消息中心 |
| 备忘录模式 | 保存对象历史状态 | 撤销、回滚 |
| 访问者模式 | 数据结构和操作分离 | AST、规则引擎 |
| 解释器模式 | 解释特定语法 | 表达式解析 |

---

## 11. 策略模式

### 实现原理

定义一组算法或业务策略，运行时根据条件选择不同实现。

```java
public interface PayStrategy {
    void pay();
}
```

```java
public class WechatPayStrategy implements PayStrategy {
    public void pay() {
        System.out.println("微信支付");
    }
}
```

### 适用场景

- 支付方式选择。
- 优惠券计算。
- 物流计费。
- 负载均衡算法。

---

## 12. 模板方法模式

### 实现原理

父类定义流程，子类实现具体步骤。

```java
public abstract class AbstractOrderProcess {

    public final void process() {
        check();
        createOrder();
        pay();
    }

    protected abstract void check();

    protected abstract void createOrder();

    protected abstract void pay();
}
```

### 适用场景

- JdbcTemplate。
- RedisTemplate。
- 业务流程固定，但部分步骤不同。

---

## 13. 观察者模式

### 实现原理

一个对象状态变化后，通知所有观察者。

```text
事件发布者
  ↓
发布事件
  ↓
多个监听器处理
```

### 适用场景

- Spring 事件机制。
- MQ 消息订阅。
- 订单创建后通知积分、优惠券、短信系统。

---

## 14. 责任链模式

### 实现原理

多个处理器按顺序处理请求，每个处理器决定是否继续传递。

```text
请求
  ↓
Handler1
  ↓
Handler2
  ↓
Handler3
  ↓
目标方法
```

### 适用场景

- Servlet Filter。
- Spring MVC Interceptor。
- Spring Security 过滤器链。
- Dubbo Filter。
- 参数校验链。

---

## 15. 状态模式

### 实现原理

对象在不同状态下有不同的行为。

例如订单状态：

```text
待支付 -> 已支付 -> 已发货 -> 已完成
```

不同状态允许的操作不同：

```text
待支付：可以支付、可以取消
已支付：可以发货、可以退款
已完成：不能取消
```

### 适用场景

- 订单状态机。
- 审批流。
- 工单流转。
- 支付状态流转。

---

## 16. 常见设计模式面试总结

| 场景 | 常用设计模式 |
|---|---|
| Spring Bean 创建 | 工厂模式、单例模式 |
| Spring AOP | 代理模式 |
| Spring MVC | 适配器模式、责任链模式 |
| Spring 事件 | 观察者模式 |
| JdbcTemplate | 模板方法模式 |
| 支付方式选择 | 策略模式 |
| 订单状态流转 | 状态模式 |
| Filter / Interceptor | 责任链模式 |
| 复杂对象创建 | 建造者模式 |
| 统一业务入口 | 门面模式 |
| IO 流增强 | 装饰器模式 |

---

## 17. 总结

设计模式分为创建型、结构型和行为型三类。

创建型模式主要解决对象创建问题，例如单例模式、工厂模式、建造者模式。  
结构型模式主要解决对象组合和功能增强问题，例如代理模式、装饰器模式、适配器模式、门面模式。  
行为型模式主要解决对象之间的交互和职责分配问题，例如策略模式、模板方法模式、观察者模式、责任链模式、状态模式。

一句话总结：

```text
创建型解决对象怎么创建；
结构型解决对象怎么组合；
行为型解决对象之间怎么协作。
```
