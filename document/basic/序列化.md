# 序列化

## 1. 什么是序列化

序列化就是：

> 把对象转换成可以存储或传输的数据格式。

反序列化就是：

> 把存储或传输的数据重新转换成对象。

例如 Java 对象：

```java
User user = new User(1L, "Tom");
```

序列化后可能变成：

```json
{
  "id": 1,
  "name": "Tom"
}
```

或者变成二进制数据，用于网络传输或文件存储。

---

## 2. 为什么需要序列化

程序中的对象存在于内存中，不能直接保存到磁盘，也不能直接通过网络传输。

所以需要先序列化。

常见场景：

```text
网络传输
RPC 调用
缓存存储
消息队列
对象持久化
分布式 Session
深拷贝
日志记录
```

---

## 3. 序列化和反序列化流程

```text
Java 对象
   ↓ 序列化
字节数组 / JSON / XML / 二进制
   ↓ 网络传输 / 文件存储 / 缓存存储
字节数组 / JSON / XML / 二进制
   ↓ 反序列化
Java 对象
```

---

## 4. 常见序列化方式

| 序列化方式 | 特点 |
|---|---|
| Java 原生序列化 | 使用简单，但性能差、体积大 |
| JSON | 可读性好，跨语言友好 |
| XML | 可读性一般，体积大 |
| Protobuf | 性能高，体积小，跨语言 |
| Hessian | 二进制序列化，常用于 RPC |
| Kryo | 性能高，体积小，但跨语言弱 |
| Avro | 常用于大数据场景 |
| MessagePack | 类似二进制 JSON |

## 5. Java 原生序列化

Java 原生序列化需要实现：

```java
Serializable
```

示例：

```java
import java.io.Serializable;

public class User implements Serializable {

    private static final long serialVersionUID = 1L;

    private Long id;
    private String name;

    public User(Long id, String name) {
        this.id = id;
        this.name = name;
    }
}
```

序列化：

```java
ObjectOutputStream oos = new ObjectOutputStream(
        new FileOutputStream("user.obj")
);

User user = new User(1L, "Tom");

oos.writeObject(user);
oos.close();
```

反序列化：

```java
ObjectInputStream ois = new ObjectInputStream(
        new FileInputStream("user.obj")
);

User user = (User) ois.readObject();

ois.close();
```

---

## 6. Serializable 是什么

`Serializable` 是一个标记接口。

源码类似：

```java
public interface Serializable {
}
```

它没有方法，只是告诉 JVM：

```text
这个类允许被序列化
```

如果类没有实现 `Serializable`，使用 Java 原生序列化时会报错：

```text
java.io.NotSerializableException
```

---

## 7. serialVersionUID 是什么

`serialVersionUID` 是序列化版本号。

```java
private static final long serialVersionUID = 1L;
```

作用：

> 判断序列化前后的类版本是否一致。

反序列化时，JVM 会检查字节流中的 `serialVersionUID` 和当前类中的 `serialVersionUID` 是否一致。

如果不一致，会报错：

```text
InvalidClassException
```

---

## 8. 为什么要手动声明 serialVersionUID

如果不手动声明，JVM 会根据类结构自动生成。

问题是：

```text
类字段变化
方法变化
编译器不同
JDK 版本不同
```

都可能导致自动生成的 `serialVersionUID` 变化。

所以推荐手动指定：

```java
private static final long serialVersionUID = 1L;
```

---

## 9. transient 关键字

如果某个字段不想被序列化，可以使用 `transient`。

示例：

```java
public class User implements Serializable {

    private static final long serialVersionUID = 1L;

    private Long id;

    private String name;

    private transient String password;
}
```

序列化时：

```text
id 会被序列化
name 会被序列化
password 不会被序列化
```

反序列化后，`password` 会变成默认值：

```text
null
```

---

## 10. static 字段会不会被序列化

不会。

因为 `static` 属于类，不属于对象。

序列化保存的是对象状态，而不是类状态。

```java
public class User implements Serializable {

    private static String type = "USER";

    private Long id;
}
```

其中 `type` 不会被序列化。

---

## 11. Java 原生序列化的问题

| 问题 | 说明 |
|---|---|
| 性能差 | 序列化和反序列化速度较慢 |
| 体积大 | 生成的字节流比较大 |
| 跨语言差 | 主要适合 Java 体系 |
| 安全风险 | 反序列化可能导致安全漏洞 |
| 版本兼容麻烦 | 类结构变化容易出问题 |

所以在分布式系统中，一般不推荐使用 Java 原生序列化。

## 12. JSON 序列化

JSON 是最常见的文本序列化方式。

对象：

```java
User user = new User(1L, "Tom");
```

序列化为：

```json
{
  "id": 1,
  "name": "Tom"
}
```

常见框架：

```text
Jackson
Fastjson
Gson
```

---

## 13. Jackson 示例

### 13.1 对象转 JSON

```java
ObjectMapper objectMapper = new ObjectMapper();

User user = new User(1L, "Tom");

String json = objectMapper.writeValueAsString(user);

System.out.println(json);
```

输出：

```json
{"id":1,"name":"Tom"}
```

---

### 13.2 JSON 转对象

```java
String json = "{\"id\":1,\"name\":\"Tom\"}";

User user = objectMapper.readValue(json, User.class);
```

---

## 14. JSON 的优缺点

### 优点

```text
可读性好
调试方便
跨语言友好
使用简单
适合 HTTP 接口
```

### 缺点

```text
体积比二进制大
性能比二进制序列化低
字段名会占用额外空间
```

适合：

```text
前后端接口
HTTP API
配置文件
日志记录
简单消息传输
```

---

## 15. Protobuf 序列化

Protobuf 是 Google 开源的二进制序列化协议。

特点：

```text
性能高
体积小
跨语言
需要定义 schema
```

示例 `.proto` 文件：

```proto
syntax = "proto3";

message User {
  int64 id = 1;
  string name = 2;
}
```

生成代码后可以进行序列化和反序列化。

适合：

```text
RPC 调用
高性能通信
跨语言服务
大规模数据传输
```

---

## 16. Hessian 序列化

Hessian 是一种二进制序列化协议。

特点：

```text
二进制格式
跨语言
比 Java 原生序列化更紧凑
常用于 RPC 场景
```

Dubbo 早期常用 Hessian 作为序列化方案之一。

---

## 17. Kryo 序列化

Kryo 是高性能 Java 序列化框架。

特点：

```text
速度快
体积小
适合 Java 内部系统
跨语言能力弱
对类注册比较敏感
```

适合：

```text
缓存
内部 RPC
高性能 Java 服务间通信
```

---

## 18. 序列化方式对比

| 方式 | 可读性 | 性能 | 体积 | 跨语言 | 适用场景 |
|---|---|---|---|---|---|
| Java 原生 | 差 | 差 | 大 | 差 | Java 本地对象持久化 |
| JSON | 好 | 中 | 中等 | 好 | HTTP、接口、日志 |
| XML | 一般 | 差 | 大 | 好 | 老系统、配置 |

| Avro | 差 | 高 | 小 | 好 | 大数据、流处理 |

## 19. 序列化在 RPC 中的作用

RPC 调用本质是远程方法调用。

例如：

```java
userService.getUserById(1L);
```

实际需要经过网络传输。

调用参数需要序列化：

```text
Long id = 1
   ↓
字节流
   ↓
网络传输
```

服务端收到后反序列化：

```text
字节流
   ↓
Long id = 1
```

执行结果也要序列化后返回。

RPC 流程：

```text
客户端对象参数
   ↓ 序列化
网络传输
   ↓ 反序列化
服务端执行方法
   ↓ 序列化返回值
网络传输
   ↓ 反序列化
客户端得到结果
```

常见 RPC 框架：

```text
Dubbo
gRPC
Thrift
Feign
```

其中：

```text
Dubbo 常用 Hessian、Kryo、Fastjson、Protobuf 等
gRPC 默认使用 Protobuf
Feign 常用 JSON
```

## 20. 序列化在 MQ 中的作用

发送消息时，消息对象需要转换成可传输的数据。

例如订单消息：

```java
OrderMessage message = new OrderMessage();
message.setOrderId("1001");
message.setUserId("2001");
```

发送到 MQ 前：

```text
OrderMessage 对象
   ↓ 序列化
JSON / 二进制
   ↓
MQ
```

消费者收到消息后：

```text
JSON / 二进制
   ↓ 反序列化
OrderMessage 对象
```

常见消息序列化格式：

```text
JSON
Protobuf
Avro
MessagePack
```

## 21. 序列化在 Redis 中的作用

Redis 存储的是字符串或字节数组。

如果要把对象存入 Redis，需要序列化。

```java
redisTemplate.opsForValue().set("user:1", user);
```

底层会把 `user` 序列化后存储。

常见 Redis 序列化方式：

| 方式 | 说明 |
|---|---|
| JdkSerializationRedisSerializer | Java 原生序列化 |
| Jackson2JsonRedisSerializer | JSON 序列化 |
| GenericJackson2JsonRedisSerializer | 通用 JSON 序列化 |
| StringRedisSerializer | 字符串序列化 |
| FastJsonRedisSerializer | Fastjson 序列化 |

---

## 22. Redis 为什么不推荐 JDK 序列化

JDK 序列化存入 Redis 后通常是二进制格式，可读性差。

例如 Redis 中看到：

```text
\xac\xed\x00\x05sr...
```

缺点：

```text
不可读
体积大
跨语言差
调试困难
类变更容易出问题
```

所以更推荐：

```text
Key 使用 StringRedisSerializer
Value 使用 JSON 序列化
```

## 23. Spring Boot Redis 序列化示例

```java
@Bean
public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
    RedisTemplate<String, Object> redisTemplate = new RedisTemplate<>();

    redisTemplate.setConnectionFactory(factory);

    StringRedisSerializer stringSerializer = new StringRedisSerializer();
    GenericJackson2JsonRedisSerializer jsonSerializer =
            new GenericJackson2JsonRedisSerializer();

    redisTemplate.setKeySerializer(stringSerializer);
    redisTemplate.setHashKeySerializer(stringSerializer);

    redisTemplate.setValueSerializer(jsonSerializer);
    redisTemplate.setHashValueSerializer(jsonSerializer);

    redisTemplate.afterPropertiesSet();

    return redisTemplate;
}
```

## 24. 反序列化安全问题

反序列化可能存在安全风险。

如果反序列化不可信数据，攻击者可能构造恶意字节流，触发危险代码执行。

风险场景：

```text
Java 原生反序列化
Fastjson autoType
不可信输入直接反序列化
历史漏洞组件
```

安全建议：

```text
不要反序列化不可信数据
禁用危险 autoType
使用白名单限制类型
升级序列化库版本
外部接口优先使用 JSON DTO
避免直接暴露 Java 原生反序列化入口
```

---

## 25. 序列化版本兼容问题

类结构变化可能导致反序列化失败或数据丢失。

常见变化：

```text
新增字段
删除字段
字段改名
字段类型变化
类包名变化
serialVersionUID 变化
```

例如：

```java
public class User implements Serializable {
    private Long id;
    private String name;
}
```

后来改成：

```java
public class User implements Serializable {
    private Long id;
    private Integer age;
}
```

旧数据反序列化可能出现兼容问题。

---

## 26. 如何保证序列化兼容性

建议：

```text
手动声明 serialVersionUID
尽量只新增字段，不随意删除字段
不要随意修改字段类型
不要随意修改类名和包名
接口传输使用 DTO
消息体设计要考虑版本号
字段变更要兼容旧消费者
```

消息体可以加版本号：

```json
{
  "version": 1,
  "orderId": "1001",
  "userId": "2001"
}
```

## 27. Java 原生序列化注意事项

```text
类必须实现 Serializable
父类如果没有实现 Serializable，需要有无参构造
建议手动声明 serialVersionUID
transient 字段不会被序列化
static 字段不会被序列化
反序列化不会调用普通构造方法
不要反序列化不可信数据
```

## 28. 序列化和深拷贝

序列化可以实现深拷贝。

思路：

```text
对象 -> 序列化成字节数组 -> 反序列化成新对象
```

示例：

```java
public static <T extends Serializable> T deepCopy(T object) throws Exception {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    ObjectOutputStream oos = new ObjectOutputStream(bos);
    oos.writeObject(object);

    ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
    ObjectInputStream ois = new ObjectInputStream(bis);

    return (T) ois.readObject();
}
```

缺点：

```text
性能较差
所有关联对象都要实现 Serializable
不适合高频调用
```

## 29. 序列化选型建议

| 场景 | 推荐方式 |
|---|---|
| HTTP 接口 | JSON |
| 前后端交互 | JSON |
| 内部 RPC 高性能调用 | Protobuf / Hessian / Kryo |
| 跨语言 RPC | Protobuf |
| Redis 缓存 | JSON / String |
| Kafka / MQ 消息 | JSON / Protobuf / Avro |
| 大数据场景 | Avro / Protobuf |
| Java 本地对象存储 | Java 原生序列化，不太推荐 |
| 调试友好优先 | JSON |
| 性能和体积优先 | Protobuf / Kryo |

## 30. 面试常问问题

### 30.1 什么是序列化？

序列化就是把对象转换成可以存储或传输的数据格式，比如字节流、JSON、XML、二进制等。

反序列化就是把这些数据重新转换成对象。

---

### 30.2 为什么需要序列化？

因为对象存在于内存中，不能直接进行网络传输或持久化。

所以需要序列化后再进行：

```text
网络传输
磁盘存储
缓存存储
消息队列传输
RPC 调用
```

---

### 30.3 Serializable 的作用是什么？

`Serializable` 是 Java 原生序列化的标记接口。

一个类实现了 `Serializable`，表示该类对象允许被序列化。

---

### 30.4 serialVersionUID 有什么用？

`serialVersionUID` 用于标识类的序列化版本。

反序列化时，JVM 会校验字节流中的 `serialVersionUID` 和当前类中的是否一致。

如果不一致，会抛出：

```text
InvalidClassException
```

---

### 30.5 transient 有什么用？

`transient` 修饰的字段不会被序列化。

常用于：

```text
密码
密钥
临时字段
不需要持久化的数据
```

---

### 30.6 static 字段会被序列化吗？

不会。

因为 `static` 字段属于类，不属于对象。

序列化保存的是对象状态，而不是类状态。

---

### 30.7 Java 原生序列化有什么缺点？

```text
性能差
序列化结果体积大
跨语言能力差
可读性差
安全风险高
版本兼容麻烦
```

---

### 30.8 JSON 和 Protobuf 怎么选？

JSON：

```text
可读性好
调试方便
适合 HTTP 接口和前后端交互
```

Protobuf：

```text
性能高
体积小
适合 RPC、高性能通信、跨语言服务
```

---

### 30.9 反序列化有什么安全风险？

如果反序列化不可信数据，攻击者可能构造恶意数据触发漏洞，严重时可能导致远程代码执行。

所以不要随意反序列化外部不可信数据。

## 31. 总结

序列化就是把内存中的对象转换成可以存储或传输的数据格式，比如字节流、JSON、XML 或二进制协议。反序列化就是把这些数据重新转换成对象。

在分布式系统中，序列化非常常见，比如 RPC 调用、消息队列、Redis 缓存、分布式 Session、对象持久化等场景都需要序列化。Java 原生序列化通过实现 `Serializable` 接口完成，但它存在性能差、体积大、跨语言能力差和安全风险等问题，所以实际项目中更常用 JSON、Protobuf、Hessian、Kryo 等序列化方式。

如果是 HTTP 接口或前后端交互，一般使用 JSON；如果是高性能 RPC 或跨语言通信，可以使用 Protobuf；如果是 Java 内部高性能调用，可以考虑 Kryo 或 Hessian。

Java 原生序列化中需要注意 `serialVersionUID`，它用于版本兼容校验；`transient` 修饰的字段不会被序列化；`static` 字段属于类，不属于对象，也不会被序列化。同时反序列化不可信数据存在安全风险，实际开发中要避免直接反序列化外部输入。

---

## 32. 一句话总结

> 序列化就是把对象转换成可存储、可传输的数据格式，反序列化就是把数据还原成对象；它广泛用于 RPC、缓存、消息队列和网络通信，实际选型要综合考虑性能、体积、可读性、跨语言能力和安全性。
