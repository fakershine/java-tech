# 登录系统设计总结

登录系统的核心目标是：**验证用户身份，并为后续请求生成可信的登录态**。

核心流程：

```text
用户提交账号密码
  ↓
服务端校验身份
  ↓
生成登录凭证 Token / Session
  ↓
客户端保存凭证
  ↓
后续请求携带凭证
  ↓
服务端校验凭证并识别用户
```

---

## 1. 登录系统核心功能

| 功能 | 说明 |
|---|---|
| 用户注册 | 创建账号 |
| 用户登录 | 校验账号密码 |
| 登录态管理 | Session / Token / JWT |
| 密码加密 | 防止明文存储 |
| 验证码 | 防暴力破解 |
| 多端登录 | Web、App、小程序 |
| 退出登录 | 清除登录态 |
| Token 刷新 | 延长登录有效期 |
| 权限加载 | 登录后加载角色和权限 |
| 风控安全 | 防刷、防爆破、异地登录提醒 |

---

## 2. 登录方式

常见登录方式：

```text
账号密码登录
手机号验证码登录
邮箱验证码登录
第三方登录
扫码登录
单点登录 SSO
```

普通后台系统常用：

```text
账号密码 + 验证码 + Token
```

移动端常用：

```text
手机号验证码 + Token
```

## 3. 数据库表设计

### 用户表

```sql
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(64) NOT NULL,
    password VARCHAR(128) NOT NULL,
    phone VARCHAR(32),
    email VARCHAR(128),
    status TINYINT NOT NULL,
    last_login_time DATETIME,
    create_time DATETIME,
    update_time DATETIME,
    UNIQUE KEY uk_username(username),
    UNIQUE KEY uk_phone(phone)
);
```

### 登录日志表

```sql
CREATE TABLE login_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT,
    username VARCHAR(64),
    login_ip VARCHAR(64),
    user_agent VARCHAR(512),
    login_result TINYINT,
    fail_reason VARCHAR(255),
    create_time DATETIME
);
```

## 4. 密码存储设计

密码不能明文存储。

推荐：

```text
BCrypt / PBKDF2 / Argon2
```

示例：

```text
原始密码
  ↓
加盐 Hash
  ↓
存储 Hash 结果
```

登录校验时：

```text
用户输入密码
  ↓
使用相同算法校验
  ↓
匹配成功才允许登录
```

不推荐：

```text
MD5
SHA1
明文密码
简单加盐 MD5
```

---

## 5. 账号密码登录流程

```text
1. 用户输入账号、密码、验证码。
2. 校验验证码是否正确。
3. 根据账号查询用户。
4. 判断用户是否存在。
5. 判断用户状态是否正常。
6. 校验密码是否正确。
7. 查询用户角色和权限。
8. 生成 Token。
9. 将 Token 和用户信息写入 Redis。
10. 返回 Token 给客户端。
11. 记录登录日志。
```

## 6. Token 登录态设计

### Redis Token 方案

登录成功后生成随机 Token：

```text
token = UUID / 随机字符串
```

Redis 存储：

```text
login:token:{token} -> userId、username、roles、permissions
```

设置过期时间：

```text
TTL = 2 小时 / 7 天
```

后续请求：

```text
请求 Header 携带 Token
  ↓
服务端从 Redis 查询 Token
  ↓
查到：登录有效
  ↓
查不到：登录过期
```

### 优势

- 服务端可主动踢人。
- 可控制 Token 失效。
- 权限变更后可清理缓存。
- 安全性较好。

### 劣势

- 依赖 Redis。
- Redis 故障会影响登录态。
- 每次请求需要查 Redis。

---

## 7. JWT 登录态设计

JWT 由三部分组成：

```text
Header.Payload.Signature
```

登录成功后生成 JWT：

```text
JWT 中保存 userId、username、过期时间等信息
```

后续请求：

```text
客户端携带 JWT
  ↓
服务端校验签名和过期时间
  ↓
解析用户身份
```

### 优势

- 服务端无状态。
- 不需要每次查 Redis。
- 适合分布式系统。
- 跨服务传递方便。

### 劣势

- Token 签发后不容易主动失效。
- 权限变更不能立即生效。
- Token 泄露后风险较高。
- 不适合存敏感信息。

### 优化

```text
短有效期 AccessToken
  +
长有效期 RefreshToken
  +
Redis 黑名单 / tokenVersion
```

## 8. Token 刷新机制

常见设计：

```text
AccessToken：短期有效，例如 2 小时
RefreshToken：长期有效，例如 7 天
```

流程：

```text
AccessToken 过期
  ↓
客户端使用 RefreshToken 请求刷新
  ↓
服务端校验 RefreshToken
  ↓
生成新的 AccessToken
  ↓
返回客户端
```

好处：

```text
提升安全性
减少频繁登录
支持长期登录
```

---

## 9. 退出登录

退出登录时：

```text
客户端请求 logout
  ↓
服务端删除 Redis 中的 Token
  ↓
客户端清除本地 Token
  ↓
后续请求无法通过认证
```

如果是 JWT：

```text
可以将 JWT 加入 Redis 黑名单
或者更新用户 tokenVersion
```

## 10. 登录拦截流程

可以在网关、过滤器或拦截器中校验登录态。

```text
请求进入系统
  ↓
获取 Header 中的 Token
  ↓
判断 Token 是否为空
  ↓
校验 Token 是否有效
  ↓
解析用户信息
  ↓
放入 ThreadLocal / 请求上下文
  ↓
放行请求
```

示例 Header：

```http
Authorization: Bearer xxxxx
```

## 11. 权限加载

登录成功后一般会加载：

```text
用户信息
角色列表
权限码列表
菜单列表
数据权限范围
```

权限缓存：

```text
user:permission:{userId}
user:role:{userId}
```

后续鉴权时直接从缓存获取，避免频繁查库。

## 12. 防暴力破解设计

常见策略：

```text
登录失败次数限制
验证码
IP 限流
账号锁定
设备指纹
黑名单
异地登录提醒
风控评分
```

示例：

```text
同一账号 5 分钟内连续失败 5 次
  ↓
锁定 30 分钟
```

Redis Key：

```text
login:fail:{username}
login:limit:ip:{ip}
```

## 13. 验证码设计

验证码适用场景：

```text
登录失败次数过多
高风险 IP
频繁登录请求
注册
找回密码
```

验证码类型：

```text
图形验证码
短信验证码
邮箱验证码
滑块验证码
行为验证码
```

注意：

```text
验证码需要设置过期时间
验证码使用后立即删除
短信验证码要限制发送频率
```

## 14. 多端登录设计

常见策略：

### 允许多端登录

```text
一个用户可以同时在 Web、App、小程序登录
```

Token Key：

```text
login:token:{token}
user:tokens:{userId}
```

---

### 单端登录

```text
同一用户只能保持一个有效 Token
```

登录时：

```text
新登录成功
  ↓
删除旧 Token
  ↓
保存新 Token
```

Redis Key：

```text
user:login:{userId} -> token
```

---

### 按设备互斥

```text
Web 一个
App 一个
小程序一个
```

Redis Key：

```text
user:login:{userId}:web
user:login:{userId}:app
```

## 15. 单点登录 SSO

SSO 解决：

```text
一次登录，多系统共享登录态
```

基本流程：

```text
用户访问系统 A
  ↓
未登录，跳转认证中心
  ↓
认证中心登录成功
  ↓
生成全局 Ticket / Token
  ↓
跳回系统 A
  ↓
系统 A 校验 Ticket
  ↓
建立本系统登录态
```

适用场景：

```text
多个后台系统
企业内部系统
统一认证中心
```

## 16. 安全设计要点

- 密码必须加密存储。
- 登录接口要限流。
- Token 要设置过期时间。
- 敏感操作需要二次验证。
- 登录失败次数要限制。
- 验证码不能长期有效。
- Token 不要放 URL 参数中。
- 推荐使用 HTTPS。
- JWT 不存敏感数据。
- 退出登录要清除服务端登录态。
- 权限变更后要让旧权限及时失效。

## 17. 推荐架构

```text
客户端
  ↓
网关 / 过滤器
  ↓
认证服务
  ↓
Redis 登录态
  ↓
用户服务
  ↓
权限服务
```

登录链路：

```text
账号密码
  ↓
验证码校验
  ↓
用户校验
  ↓
密码校验
  ↓
生成 Token
  ↓
缓存登录态
  ↓
返回 Token
```

请求链路：

```text
请求携带 Token
  ↓
网关校验 Token
  ↓
解析用户身份
  ↓
写入请求 Header
  ↓
业务服务处理请求
```

---

## 18. 总结

登录系统的核心是认证用户身份，并生成登录态。常见方案有 Session、Redis Token 和 JWT。

传统 Web 系统可以使用 Session；分布式系统中更常用 Redis Token，把 Token 和用户信息存入 Redis，方便主动失效和权限刷新；如果追求无状态，可以使用 JWT，但要注意 Token 主动失效和泄露风险。

登录系统还要考虑密码加密、验证码、防暴力破解、Token 过期刷新、多端登录、退出登录、权限加载、登录日志和风控安全。

一句话总结：

```text
登录系统设计 = 用户认证 + 密码安全 + Token 登录态 + Redis 缓存 + 权限加载 + 风控限流 + 登录审计。
```
