# 基于统一日志工具类的动态日志脱敏设计方案

## 1. 背景

在 Java 后端系统中，业务代码经常会通过日志打印用户相关信息，例如：

- 手机号
- 身份证号
- 银行卡号
- 邮箱
- 姓名
- 地址
- Token
- Cookie
- SessionId
- 密码
- 第三方接口返回数据

如果这些敏感信息未经处理直接打印到日志文件、ELK、Loki、ClickHouse、Kafka 等日志系统中，会带来较大的数据安全风险。

为了解决这个问题，可以设计一套**基于统一日志工具类的动态日志脱敏方案**。

该方案的核心思想是：

> 业务代码不直接使用 `log.info()`、`log.error()` 等原生日志方法，而是统一调用封装后的 `LogUtils` 或 `BizLogger`，在工具类内部先完成日志格式化和脱敏，再调用真正的日志框架输出。

---

## 2. 设计目标

### 2.1 功能目标

- 统一业务日志打印入口
- 支持手机号、身份证、邮箱、银行卡、Token 等敏感信息脱敏
- 支持正则表达式脱敏
- 支持通过配置中心动态刷新脱敏规则
- 支持开启或关闭日志脱敏
- 支持日志级别判断，避免无效字符串拼接
- 支持异常日志打印
- 支持规则校验和异常降级

### 2.2 非功能目标

- 实现简单，易于落地
- 不强依赖 Logback / Log4j2 扩展机制
- 对现有系统可渐进式改造
- 配置错误不能影响业务系统稳定性
- 脱敏规则刷新时不影响正在打印日志的线程
- 具备较好的性能表现

---

## 3. 适用场景

该方案适合以下场景：

- 项目规模中小型
- 希望快速落地日志脱敏
- 暂时不想改造 Logback / Log4j2
- 可以推动团队统一日志规范
- 希望先对核心业务日志进行脱敏
- 存量系统需要渐进式改造

---

## 5. 核心思路

原始写法：

```java
private static final Logger log = LoggerFactory.getLogger(UserService.class);

log.info("用户登录成功，userId={}，phone={}，idCard={}", userId, phone, idCard);
```

改造后写法：

```java
private static final Logger log = LoggerFactory.getLogger(UserService.class);

LogUtils.info(log, "用户登录成功，userId={}，phone={}，idCard={}", userId, phone, idCard);
```

或者进一步封装为：

```java
private static final BizLogger log = BizLoggerFactory.getLogger(UserService.class);

log.info("用户登录成功，userId={}，phone={}，idCard={}", userId, phone, idCard);
```

最终日志输出：

```text
用户登录成功，userId=10001，phone=138****5678，idCard=110101********1234
```

## 6. 方案优缺点

### 6.1 优点

| 优点 | 说明 |
|---|---|
| 实现简单 | 不需要深入改造日志框架 |
| 易于理解 | 本质是统一日志入口 |
| 可动态配置 | 配置中心变化后刷新脱敏规则 |
| 可渐进式改造 | 可以先改核心业务代码 |
| 可控性强 | 哪些日志走脱敏由业务控制 |
| 侵入日志框架少 | 不依赖 Logback Converter 或 Appender |

---

### 6.2 缺点

| 缺点 | 说明 |
|---|---|
| 需要改业务代码 | 原来的 `log.info()` 需要替换 |
| 可能被绕过 | 开发人员直接使用原生 `log.info()` 不会脱敏 |
| 覆盖不完整 | 第三方组件日志无法处理 |
| 存量改造有成本 | 老项目需要逐步替换 |
| 依赖团队规范 | 需要约束开发人员统一使用工具类 |

## 12. 预编译脱敏规则

```java
import java.util.regex.Pattern;

public class CompiledMaskRule {

    private final String name;

    private final Pattern pattern;

    private final String replacement;

    public CompiledMaskRule(String name, String pattern, String replacement) {
        this.name = name;
        this.pattern = Pattern.compile(pattern);
        this.replacement = replacement;
    }

    public String getName() {
        return name;
    }

    public Pattern getPattern() {
        return pattern;
    }

    public String getReplacement() {
        return replacement;
    }
}
```

## 13. 正则脱敏器实现

```java
import java.util.List;

public class RegexLogMasker implements LogMasker {

    private final List<CompiledMaskRule> rules;

    public RegexLogMasker(List<CompiledMaskRule> rules) {
        this.rules = rules;
    }

    @Override
    public String mask(String message) {
        if (message == null || message.isEmpty()) {
            return message;
        }

        String result = message;

        for (CompiledMaskRule rule : rules) {
            result = rule.getPattern()
                    .matcher(result)
                    .replaceAll(rule.getReplacement());
        }

        return result;
    }
}
```

## 14. 脱敏规则管理器

### 14.1 设计说明

`MaskRuleManager` 用于维护当前生效的脱敏器。

核心点：

- 使用 `AtomicReference` 保存当前脱敏器
- 读路径无锁
- 配置刷新时原子替换
- 配置错误时保留旧规则
- 不影响正在打印日志的线程

---

### 14.2 代码实现

```java
import java.util.List;
import java.util.concurrent.atomic.AtomicReference;

public class MaskRuleManager {

    private final AtomicReference<LogMasker> maskerRef =
            new AtomicReference<>(message -> message);

    public String mask(String message) {
        return maskerRef.get().mask(message);
    }

    public void refresh(List<CompiledMaskRule> rules) {
        if (rules == null || rules.isEmpty()) {
            maskerRef.set(message -> message);
            return;
        }

        LogMasker newMasker = new RegexLogMasker(rules);
        maskerRef.set(newMasker);
    }
}
```

## 15. 统一日志工具类 LogUtils

### 15.1 设计说明

`LogUtils` 是业务代码直接调用的日志工具类。

它主要负责：

1. 判断日志级别是否开启；
2. 使用 SLF4J 的 `MessageFormatter` 格式化日志；
3. 调用 `MaskRuleManager` 进行脱敏；
4. 调用真正的 `Logger` 输出日志；
5. 兼容异常日志。

---

### 15.2 代码实现

```java
import org.slf4j.Logger;
import org.slf4j.helpers.FormattingTuple;
import org.slf4j.helpers.MessageFormatter;

import java.util.List;

public final class LogUtils {

    private static final MaskRuleManager MASK_RULE_MANAGER = new MaskRuleManager();

    private LogUtils() {
    }

    public static void refreshRules(List<CompiledMaskRule> rules) {
        MASK_RULE_MANAGER.refresh(rules);
    }

    public static void info(Logger logger, String format, Object... args) {
        if (!logger.isInfoEnabled()) {
            return;
        }

        String message = formatMessage(format, args);
        String maskedMessage = MASK_RULE_MANAGER.mask(message);

        logger.info(maskedMessage);
    }

    public static void debug(Logger logger, String format, Object... args) {
        if (!logger.isDebugEnabled()) {
            return;
        }

        String message = formatMessage(format, args);
        String maskedMessage = MASK_RULE_MANAGER.mask(message);

        logger.debug(maskedMessage);
    }

    public static void warn(Logger logger, String format, Object... args) {
        if (!logger.isWarnEnabled()) {
            return;
        }

        String message = formatMessage(format, args);
        String maskedMessage = MASK_RULE_MANAGER.mask(message);

        logger.warn(maskedMessage);
    }

    public static void error(Logger logger, String format, Object... args) {
        if (!logger.isErrorEnabled()) {
            return;
        }

        FormattingTuple tuple = MessageFormatter.arrayFormat(format, args);

        String message = tuple.getMessage();
        Throwable throwable = tuple.getThrowable();

        String maskedMessage = MASK_RULE_MANAGER.mask(message);

        if (throwable != null) {
            logger.error(maskedMessage, throwable);
        } else {
            logger.error(maskedMessage);
        }
    }

    private static String formatMessage(String format, Object... args) {
        FormattingTuple tuple = MessageFormatter.arrayFormat(format, args);
        return tuple.getMessage();
    }
}
```

## 17. 配置中心动态刷新

### 17.1 刷新流程

```text
配置中心规则发生变化
  │
  ▼
应用监听配置变更
  │
  ▼
读取最新配置
  │
  ▼
校验规则
  │
  ▼
预编译正则
  │
  ├── 成功：刷新 LogUtils 中的规则
  │
  └── 失败：保留旧规则并告警
  │
  ▼
新规则实时生效
```

---

### 17.2 刷新实现

```java
import java.util.List;
import java.util.regex.Pattern;

public class MaskConfigRefresher {

    public void refresh(MaskProperties properties) {
        if (properties == null || !properties.isEnabled()) {
            LogUtils.refreshRules(List.of());
            return;
        }

        List<MaskRule> regexRules = properties.getRegexRules();

        if (regexRules == null || regexRules.isEmpty()) {
            LogUtils.refreshRules(List.of());
            return;
        }

        List<CompiledMaskRule> rules = regexRules.stream()
                .filter(MaskRule::isEnabled)
                .map(rule -> {
                    validateRule(rule);

                    return new CompiledMaskRule(
                            rule.getName(),
                            rule.getPattern(),
                            rule.getReplacement()
                    );
                })
                .toList();

        LogUtils.refreshRules(rules);
    }

    private void validateRule(MaskRule rule) {
        if (rule.getPattern() == null || rule.getPattern().isEmpty()) {
            throw new IllegalArgumentException("脱敏规则 pattern 不能为空，rule=" + rule.getName());
        }

        if (rule.getReplacement() == null) {
            throw new IllegalArgumentException("脱敏规则 replacement 不能为空，rule=" + rule.getName());
        }

        Pattern.compile(rule.getPattern());
    }
}
```

### 17.3 安全刷新实现

为了避免错误配置影响业务系统，推荐增加安全刷新包装：

```java
public class SafeMaskConfigRefresher {

    private final MaskConfigRefresher refresher = new MaskConfigRefresher();

    public void safeRefresh(MaskProperties properties) {
        try {
            refresher.refresh(properties);
        } catch (Exception e) {
            // 不能抛出异常影响业务服务
            // 继续使用旧规则
            // 实际项目中这里应该接入日志和监控告警
            System.err.println("日志脱敏规则刷新失败，继续使用旧规则：" + e.getMessage());
        }
    }
}
```

## 23. 日志打印规范

### 23.1 禁止直接打印敏感信息

不推荐：

```java
log.info("用户手机号：{}", phone);
```

推荐：

```java
LogUtils.info(log, "用户手机号：{}", phone);
```

或者：

```java
bizLogger.info("用户手机号：{}", phone);
```

---

### 23.2 禁止直接打印完整对象

不推荐：

```java
log.info("用户信息：{}", JSON.toJSONString(user));
```

原因：

- 对象中可能包含密码、Token、身份证等敏感字段
- 字段不可控
- 日志体积大
- 不利于问题定位

推荐：

```java
LogUtils.info(log, "用户登录成功，userId={}，phone={}，requestId={}",
        userId, phone, requestId);
```

---

## 24. 性能优化

日志脱敏位于日志打印链路中，需要注意性能。

### 24.1 优化建议

| 优化点 | 说明 |
|---|---|
| 先判断日志级别 | `logger.isInfoEnabled()` 不通过则不格式化 |
| 正则预编译 | 使用 `Pattern.compile()` 预编译 |
| 规则原子替换 | 使用 `AtomicReference` |
| 控制规则数量 | 避免每条日志执行过多正则 |
| 避免复杂正则 | 防止灾难性回溯 |
| 异常降级 | 脱敏失败时不影响业务 |
| 减少对象创建 | 避免每次打印日志都创建规则对象 |
| 使用异步日志 | 高并发场景配合异步日志 |

## 25. 容错设计

### 25.1 配置错误场景

配置中心可能出现以下问题：

- 正则表达式语法错误
- replacement 配置错误
- YAML 格式错误
- 规则为空
- 规则数量过多
- 配置中心短暂不可用

---

### 25.2 处理原则

必须遵循：

```text
新规则先校验
校验成功再替换
校验失败保留旧规则
不能影响业务线程
```

---

### 25.3 推荐处理方式

| 异常情况 | 处理方式 |
|---|---|
| 新规则正则错误 | 保留旧规则 |
| 配置为空 | 根据策略关闭脱敏或保留旧规则 |
| 配置中心不可用 | 使用本地缓存规则 |
| 脱敏过程异常 | 输出原日志或降级日志 |
| 规则刷新失败 | 记录错误并告警 |

## 31. 总结

基于统一日志工具类的动态日志脱敏方案，本质上是：

> 将业务日志打印入口统一收敛到 `LogUtils` 或 `BizLogger`，在日志真正输出前完成格式化和脱敏处理。

该方案实现简单、容易理解、适合快速落地，尤其适合希望先对核心业务日志进行治理的系统。

但它也有明显边界：

- 无法覆盖开发人员绕过工具类直接打印的日志；
- 无法覆盖第三方组件日志；
- 需要团队规范和 Code Review 配合；
- 存量系统需要逐步替换日志调用方式。

因此，建议短期可以使用该方案快速治理核心日志，长期可以逐步演进为：

```text
统一日志工具类脱敏
        +
日志框架层统一脱敏
        +
日志采集链路二次脱敏
```

最终形成完整的日志安全防护体系。
