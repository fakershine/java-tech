# 基于配置中心的动态日志脱敏设计方案

## 1. 背景

在 Java 后端系统中，日志是排查问题、链路追踪、监控告警的重要依据。

但在实际业务中，日志中经常会出现以下敏感信息：

- 手机号
- 身份证号
- 银行卡号
- 邮箱
- 姓名
- 地址
- 密码
- Token
- Cookie
- SessionId
- AccessToken
- RefreshToken
- 第三方接口返回的敏感字段

如果这些信息未经处理直接打印到日志文件、ELK、Loki、ClickHouse、Kafka 等系统中，会带来较大的数据安全风险。

因此，需要设计一套**基于配置中心动态控制的日志脱敏方案**，使系统可以在不重启应用的情况下，动态控制哪些字段、哪些内容需要脱敏。

---

## 2. 设计目标

### 2.1 功能目标

- 支持通过配置中心动态开启或关闭日志脱敏
- 支持动态新增、修改、删除脱敏规则
- 支持手机号、身份证、银行卡、邮箱、Token 等常见敏感信息脱敏
- 支持正则表达式脱敏
- 支持 JSON 字段脱敏
- 支持 Key-Value 格式日志脱敏
- 支持配置变更后实时生效
- 支持脱敏规则校验和失败回滚

### 2.2 非功能目标

- 对业务代码低侵入
- 不影响正常日志打印
- 脱敏逻辑不能影响应用稳定性
- 配置错误时不能导致服务异常
- 具备较好的性能表现
- 支持监控、告警和灰度发布

---

## 3. 整体架构

```text
配置中心
  │
  │ 动态下发脱敏配置
  ▼
脱敏配置监听器
  │
  │ 解析配置、校验规则、预编译正则
  ▼
脱敏规则管理器 MaskRuleManager
  │
  │ AtomicReference 原子替换当前规则
  ▼
日志脱敏组件
  │
  │ Logback Converter / Layout / Appender
  │
  │ Log4j2 RewritePolicy / Layout / Appender
  ▼
日志输出
  │
  ├── Console
  ├── File
  ├── Kafka
  ├── ELK
  ├── Loki
  └── ClickHouse
```

## 4. 核心设计思路

整体思路是：

> 业务代码正常打印日志，日志框架在真正输出日志之前，统一调用脱敏组件，根据配置中心中的脱敏规则对日志内容进行处理。

也就是说，业务代码仍然可以这样写：

```java
log.info("用户登录成功，userId={}，phone={}，idCard={}", userId, phone, idCard);
```

最终日志输出时变成：

```text
用户登录成功，userId=10001，phone=138****5678，idCard=110101********1234
```

---

## 5. 推荐实现方式

### 5.1 推荐方案：日志框架层统一脱敏

建议优先在日志框架层做统一脱敏。

常见日志框架扩展点如下：

| 日志框架 | 推荐扩展点 |
|---|---|
| Logback | MessageConverter、Layout、Encoder、Appender |
| Log4j2 | RewritePolicy、Layout、Appender |
| JSON 日志 | 自定义 JSON Encoder 或 Provider |

### 5.2 优点

- 对业务代码无侵入
- 所有日志统一治理
- 不依赖开发人员手动调用脱敏方法
- 配置中心变更后可动态生效
- 规则统一维护，便于审计
- 适合生产环境落地

### 5.3 不推荐方案

不建议只依赖业务代码手动脱敏，例如：

```java
log.info("手机号：{}", MaskUtils.maskPhone(phone));
```

这种方式存在明显问题：

- 容易遗漏
- 依赖开发人员自觉
- 存量代码改造成本高
- 第三方组件日志无法覆盖
- 统一治理能力弱

## 9. 核心接口设计

### 9.1 日志脱敏接口

```java
public interface LogMasker {

    /**
     * 对日志内容进行脱敏
     *
     * @param message 原始日志内容
     * @return 脱敏后的日志内容
     */
    String mask(String message);
}
```

---

### 9.2 组合脱敏器

```java
import java.util.List;

public class CompositeLogMasker implements LogMasker {

    private final List<LogMasker> maskers;

    public CompositeLogMasker(List<LogMasker> maskers) {
        this.maskers = maskers;
    }

    @Override
    public String mask(String message) {
        if (message == null || message.isEmpty()) {
            return message;
        }

        String result = message;

        for (LogMasker masker : maskers) {
            result = masker.mask(result);
        }

        return result;
    }
}
```

推荐脱敏顺序：

```text
JSON 字段脱敏
  ↓
Key-Value 字段脱敏
  ↓
正则兜底脱敏
```

## 10. 正则脱敏实现

### 10.1 预编译规则对象

```java
import java.util.regex.Pattern;

public class CompiledMaskRule {

    private final String name;

    private final Pattern pattern;

    private final String replacement;

    public CompiledMaskRule(String name, String pattern, String replacement) {
        this.name = name;
        this.pattern = Pattern.compile(pattern);
        this.replacement = replacement;
    }

    public String getName() {
        return name;
    }

    public Pattern getPattern() {
        return pattern;
    }

    public String getReplacement() {
        return replacement;
    }
}
```

---

### 10.2 正则脱敏器

```java
import java.util.List;

public class RegexLogMasker implements LogMasker {

    private final List<CompiledMaskRule> rules;

    public RegexLogMasker(List<CompiledMaskRule> rules) {
        this.rules = rules;
    }

    @Override
    public String mask(String message) {
        if (message == null || message.isEmpty()) {
            return message;
        }

        String result = message;

        for (CompiledMaskRule rule : rules) {
            result = rule.getPattern()
                    .matcher(result)
                    .replaceAll(rule.getReplacement());
        }

        return result;
    }
}
```

## 11. 常见脱敏策略实现

### 11.1 手机号脱敏

```java
public static String maskPhone(String phone) {
    if (phone == null || phone.length() < 7) {
        return phone;
    }

    return phone.substring(0, 3)
            + "****"
            + phone.substring(phone.length() - 4);
}
```

示例：

```text
13812345678 -> 138****5678
```

---

### 11.2 邮箱脱敏

```java
public static String maskEmail(String email) {
    if (email == null || !email.contains("@")) {
        return email;
    }

    int index = email.indexOf("@");
    String prefix = email.substring(0, index);
    String domain = email.substring(index);

    if (prefix.length() <= 1) {
        return "*" + domain;
    }

    return prefix.charAt(0) + "****" + domain;
}
```

示例：

```text
zhangsan@example.com -> z****@example.com
```

## 12. 脱敏规则管理器

### 12.1 设计原则

脱敏规则管理器负责维护当前生效的脱敏规则。

核心要求：

- 配置变更后实时刷新
- 刷新过程不影响正在打印日志的线程
- 读路径无锁
- 配置错误时继续使用旧规则
- 新规则校验通过后再替换

---

### 12.2 基于 AtomicReference 的实现

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.atomic.AtomicReference;

public class MaskRuleManager {

    private final AtomicReference<LogMasker> maskerRef =
            new AtomicReference<>(message -> message);

    public String mask(String message) {
        return maskerRef.get().mask(message);
    }

    public void refresh(MaskProperties properties) {
        if (properties == null || !properties.isEnabled()) {
            maskerRef.set(message -> message);
            return;
        }

        List<LogMasker> maskers = new ArrayList<>();

        if (properties.getJsonFields() != null && !properties.getJsonFields().isEmpty()) {
            maskers.add(new JsonFieldLogMasker(properties.getJsonFields()));
        }

        if (properties.getKeyValueFields() != null && !properties.getKeyValueFields().isEmpty()) {
            maskers.add(new KeyValueLogMasker(properties.getKeyValueFields()));
        }

        if (properties.getRegexRules() != null && !properties.getRegexRules().isEmpty()) {
            List<CompiledMaskRule> compiledRules = compileRules(properties.getRegexRules());
            maskers.add(new RegexLogMasker(compiledRules));
        }

        maskerRef.set(new CompositeLogMasker(maskers));
    }

    private List<CompiledMaskRule> compileRules(List<MaskRule> rules) {
        return rules.stream()
                .filter(MaskRule::isEnabled)
                .map(rule -> new CompiledMaskRule(
                        rule.getName(),
                        rule.getPattern(),
                        rule.getReplacement()
                ))
                .toList();
    }
}
```

## 13. 安全刷新机制

### 13.1 刷新流程

```text
配置中心发生变化
  │
  ▼
应用监听到配置变更
  │
  ▼
拉取最新脱敏配置
  │
  ▼
解析配置
  │
  ▼
校验配置
  │
  ▼
预编译正则
  │
  ├── 成功：构建新的 LogMasker
  │
  └── 失败：保留旧规则并告警
  │
  ▼
AtomicReference 原子替换
  │
  ▼
新规则实时生效
```

---

### 13.2 安全刷新代码示例

```java
public class SafeMaskRuleRefresher {

    private final MaskRuleManager maskRuleManager;

    public SafeMaskRuleRefresher(MaskRuleManager maskRuleManager) {
        this.maskRuleManager = maskRuleManager;
    }

    public void safeRefresh(MaskProperties properties) {
        try {
            validate(properties);

            maskRuleManager.refresh(properties);
        } catch (Exception e) {
            // 注意：此处不能抛出异常影响业务系统
            // 继续使用旧规则
            // 同时记录错误日志并触发告警
            System.err.println("日志脱敏规则刷新失败，继续使用旧规则：" + e.getMessage());
        }
    }

    private void validate(MaskProperties properties) {
        if (properties == null) {
            return;
        }

        if (properties.getRegexRules() == null) {
            return;
        }

        for (MaskRule rule : properties.getRegexRules()) {
            if (rule.isEnabled()) {
                if (rule.getPattern() == null || rule.getPattern().isEmpty()) {
                    throw new IllegalArgumentException("脱敏规则 pattern 不能为空，rule=" + rule.getName());
                }

                if (rule.getReplacement() == null) {
                    throw new IllegalArgumentException("脱敏规则 replacement 不能为空，rule=" + rule.getName());
                }

                // 预编译校验
                Pattern.compile(rule.getPattern());
            }
        }
    }
}
```

## 14. Logback 集成方案

### 14.1 自定义 MessageConverter

```java
import ch.qos.logback.classic.pattern.MessageConverter;
import ch.qos.logback.classic.spi.ILoggingEvent;

public class MaskingMessageConverter extends MessageConverter {

    private static MaskRuleManager maskRuleManager;

    public static void setMaskRuleManager(MaskRuleManager manager) {
        maskRuleManager = manager;
    }

    @Override
    public String convert(ILoggingEvent event) {
        String message = event.getFormattedMessage();

        if (maskRuleManager == null) {
            return message;
        }

        return maskRuleManager.mask(message);
    }
}
```

## 19. 日志打印规范

### 19.1 不推荐

```java
log.info("用户完整信息：{}", JSON.toJSONString(user));
```

原因：

- 可能打印大量敏感字段
- 不易控制
- 不利于字段级脱敏
- 容易造成日志污染
- 会增加日志体积

---

### 19.2 推荐

```java
log.info("用户登录成功，userId={}，phone={}，requestId={}",
        userId, phone, requestId);
```

---

### 19.3 更推荐：结构化日志

## 20. 性能优化

日志脱敏位于日志输出链路中，如果处理不当，会影响系统性能。

### 20.1 优化建议

| 优化点 | 说明 |
|---|---|
| 正则预编译 | 使用 `Pattern.compile()` 预编译，不要每条日志重复编译 |
| AtomicReference | 规则读取无锁，刷新时原子替换 |
| 控制规则数量 | 避免每条日志执行过多正则匹配 |
| 避免复杂正则 | 防止灾难性回溯导致 CPU 飙高 |
| 字段级优先 | JSON 字段脱敏优先于全文正则 |
| 异步日志 | 使用 Logback AsyncAppender 或 Log4j2 Async Logger |
| 控制日志长度 | 对超长日志进行截断 |
| 配置开关 | 支持快速关闭高成本规则 |
| 缓存规则 | 规则预处理，不在日志打印时解析配置 |

## 21. 容错设计

### 21.1 配置错误不能影响服务

配置中心可能出现以下错误：

- YAML 格式错误
- 正则语法错误
- 替换表达式错误
- 规则为空
- 规则数量过多
- 正则存在灾难性回溯风险

正确做法是：

```text
新配置下发
  │
  ▼
解析配置
  │
  ▼
校验规则
  │
  ▼
预编译正则
  │
  ├── 成功：替换旧规则
  │
  └── 失败：继续使用旧规则
```

### 21.2 失败处理

配置刷新失败时：

- 保留旧规则
- 打印错误日志
- 推送监控告警
- 记录失败次数
- 必要时自动回滚配置

## 25. 常见问题

### 25.1 是否只处理 message 就够了？

不够。

除了 `message`，还需要关注：

- MDC
- Marker
- Throwable message
- Exception stack trace
- JSON 日志字段
- 第三方组件日志
- HTTP 请求体日志
- SQL 参数日志

---

### 25.2 是否可以完全依赖正则？

不建议。

正则适合作为兜底能力，但不适合作为唯一方案。

推荐：

```text
字段级脱敏优先，正则脱敏兜底
```

---

### 25.3 配置中心规则错误怎么办？

不能让错误规则直接生效。

正确处理方式：

```text
新规则校验失败
  ↓
继续使用旧规则
  ↓
记录错误日志
  ↓
发送告警
```

---

### 25.4 是否会影响性能？

会有一定影响，但可以通过以下方式控制：

- 正则预编译
- 减少规则数量
- 使用异步日志
- 优先字段级脱敏
- 避免复杂正则
- 对超长日志进行截断
- 增加性能监控

## 29. 总结

基于配置中心的动态日志脱敏方案，本质上是将脱敏能力从业务代码中抽离出来，统一放到日志输出链路中处理。

核心设计点包括：

1. 配置中心维护脱敏规则
2. 应用监听配置变化
3. 新规则先校验、预编译
4. 使用 `AtomicReference` 原子替换规则
5. 日志输出前统一调用脱敏组件
6. JSON 字段脱敏优先
7. Key-Value 字段脱敏补充
8. 正则脱敏兜底
9. 错误配置不能影响应用稳定性
10. 增加监控和告警
11. 配合日志打印规范一起落地

最终效果是：

> 业务代码低侵入、规则动态生效、脱敏统一治理、系统稳定性可控。
